# Same original PDF pixels: iOS Vision acquisition measurement

This research helper runs the actual source-extracted `PDFRecoveryRecognition.read` body from iOS commit `748ec016ea32b8d533df4626c3767505cc268cb2`, with unchanged `RecognizeDocumentsRequest()` and the original `min(2, 2048 / max(page bounds))` thumbnail rule. It makes exactly one native request per page on an owned iOS 27 simulator: two fixed PDFs, five pages each. No Core AI, language model, school data, model download, grammar, prompt, or oracle enters recognition.

`prepare.py` verifies whole source SHA values, requires unique declaration selectors, and copies the actual method and used types without editing their bodies. Small namespace containers retain only the real `maximumBytes` and parser-version declarations needed by the extracted code. This is not a build of the full production app. Actual Apple SDK compilation and native execution are pending until the single reviewed CI run completes; local checks only parse Swift syntax and test extraction/input identity.

The original lossless RGB PNGs are copied from Windows research commit `3aab761f4aedb8e78fedf3868e952faff190ae70`. The immutable original assembler reconstructs identical image-only PDF bytes and verifies both pinned SHA values. The native program receives those PDFs and an input identity manifest; drawing plans and expected lesson values are absent. These two controls were already used in Windows research and are not an unused holdout.

Raw output records each returned line's top candidate, confidence, actual character bounding boxes, pixel size, public `.read` return status, failure stage, and timing. The existing `.layouts` confidence predicate (finite, 0.85 through 1) and its character-box conditions are **post-observation diagnostics**, applied without a second OCR call. A low confidence line does not stop measurement of later pages. Missing candidates and bounding boxes remain explicit. A `.read` exception can occur after `Vision.perform` returned, so the report does not claim Vision itself failed or never finished. Runtime or diagnostic failures remain operational and unassessed; they are not recognition accuracy zero or correct negative rejection.

The `.read` route uses fractional thumbnail `CGSize` dimensions; production `.layouts` rounds dimensions upward and also constructs a raster. The helper calls `.read`, never `.layouts`, and records its actual image dimensions. Windows and mobile render scales therefore differ even for the same PDF, so this comparison cannot isolate OCR-engine quality from rendering. Character-box area is a sum, not a union or a proof of all original ink coverage. `inkCoverageVerified` is always false. Passing every diagnostic does not prove that text was omitted nowhere, that an empty cell is verified, or that Builder/Rules/Validator/formal recovery succeeds. Formal assessment and model qualification remain zero/unassessed.

The runner records actual simulator SDK/runtime, host CPU/RAM and native raw bytes. Simulator hardware is host-backed and is not physical iPhone memory or performance evidence. Each page has a 180-second cooperative check before/after the unchanged native request; synchronous execution is not interrupted at that deadline. A 1200-second process wall guard and owned-simulator shutdown bound the overall attempt. Only the created simulator and uniquely marked job scratch are deleted. No Actions cache or artifact is used; the full raw output and extraction receipt are printed in the job log. The workflow starts once from the dedicated feature push; do not additionally dispatch the same completed measurement.

## Detailed hierarchy observation phase

The initial ten-page observation is already published under `research-results/ios-vision-acquisition-20261004`. This separate, authorized detailed phase makes one new request per original page with exactly the same source-extracted `.read` body, default request, render rule, SDK and inputs. It changes output accessors only. The original global-line top1 record is retained. Each captured text region additionally records its exact transcript, line transcript and independently queried top1 and ordered top5 candidates, including candidate confidence and actual character boxes. A disagreement between top1 and top5.first remains an observation; no alternative is adopted.

Tables retain native row entry order, cell row/column ranges and recursively captured cell content. Merged spans are not expanded, repeated representations are not deduplicated, and no missing period is filled. Titles, paragraphs and list-item content retain their parent paths. Per-page shared caps bound containers, rows, column metadata, text regions, cells, lines, candidates, characters, contour points, UTF-8 string bytes and recursion depth. The four-MiB output accounting is a conservative estimate, not the exact serialized size; string accounting allows JSON escaping. Omission records are themselves bounded. Any omitted or unsupported content sets `hierarchyCaptureComplete=false`, with the affected path/reason/available count. Barcodes are explicitly unsupported rather than inferred as text. Transport is capped at 64 MiB. Read return, serialization completion and hierarchy completeness are reported separately, including partial results on failure.

A token in a table or global transcript may identify a representation gap in the earlier output. Absence from retained output does not prove absence from all Vision candidates, particularly after truncation or beyond top5. Pixel coordinates derive from the actual mobile render dimensions; native rendered pixels are not saved. Differences between the two native runs also retain run variability, and are not isolated effects of the serializer. Full class/day/period and lesson-field binding, complete original ink coverage, verified empty cells and formal recovery remain unassessed. No output is repaired, and no threshold, recognition language or model changes are included.
