# Independent native vector Reader probe

This opt-in diagnostic regenerates six independently invented wide timetable PDFs from the pinned public generator. No uploaded school PDF, name substitution, private image, OCR, language model, or persistence API is used. PDF/font binaries remain in owned temporary CI storage and are deleted; no artifact or cache is uploaded.

One owned iOS 27 simulator performs four baseline `71d28af` Reader-only calls, then six calls with the exact current production sources. The primary v1 unlabeled PDF remains first. The v2 pair only diagnoses unused font selection. The two negative PDFs exercise parallel mismatch and an unreadable vector body mark. The helper records all actual layouts, capture completion, errors and routes separately.

For the fixed sources, actual `PDFKitReader` output enters `PDFSchoolParser` first. Only an eligible Strict error with complete actual capture can enter `RecoveryDocumentBuilder`, source-only Rules (`providers: []`), Validator and in-memory Analysis conversion. No expected layouts, roles, evidence, blank flags or names enter those calls. `expected.json` is opened for literal 680-slot/year/term/class assertions only after production returns an Analysis. No Analysis on an error is reported as a refusal, not a missing-value repair.

The transport job can succeed while a fixture is rejected or its literal comparison fails. Inspect the per-fixture raw records and separate semantic counts. Only typed `PDFParseError.unsupported/ambiguous` count as semantic refusals; limits, cancellation, IO, arbitrary errors, unfinished Rules and unassessed structure proposals remain separate. The actual structure resolution return type contains proposals/metadata; this no-provider probe records it but does not adopt proposals. Assertion errors are unassessed, rather than literal mismatches. Full literal equality on this independently generated vector fixture does not qualify OCR, generic model recovery, physical devices, transactional persistence or manual adoption UI. Empty expected slots compare parser absence after complete Reader/parser success; they do not prove an OCR empty-cell policy.

The workflow runs four generator tests and twelve helper provenance/receipt/transport tests, compiles baseline and current sources against the actual Apple simulator SDK, and invokes each planned Reader case once. The exact public `normalPeriodTimes` array is extracted only to supply an otherwise unused return-kind compile dependency, with current source/declaration hashes and baseline declaration byte equality recorded; no Reader/parser/recovery algorithm is substituted. Source/fixture pins and exact raw UTF-8 byte hashes are emitted in numbered base64 log chunks under 8KB. Missing, reordered, duplicated, truncated or corrupted chunks cannot produce a successful readback. A data-only publication must not trigger another native run.
