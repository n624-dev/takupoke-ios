# 端末内の保存と時間割統合

[READMEに戻る](../README.md)

原本・解析結果・取得と解析の試行を分けて保存します。現在選択したファイルと、最後に正常解析できたファイルが異なる場合も、両者の来歴を保持します。時間割は保存済みの正常結果から表示時に組み立てます。

## 保存先

アプリ専用のApplication Support内に保存します。

| データ | 保存先・方式 |
| --- | --- |
| 通常時間割・時間割変更 | `SchoolMaterialsSQLite/library.sqlite` と `files/`。GRDBによるSQLite |
| 試験・返却 | `SpecialSchedulesSQLite/specials.sqlite` と `files/`。選択原本と正常解析を別テーブルへ保存 |
| 名称データ | `NameMappings/mappings.sqlite`。検証済み規則と公開revisionを一括保存 |
| リンク一覧 | `LinksAPI`。検証済みJSONとETag・公開revision |
| 日付別の授業時刻 | `TimetableTimes/current.json`。検証済み時刻と公開revision |
| 公開の学校行事 | `SchoolEventsAPI`。年度別のJSON・APIのETag・取得日時 |
| 通知の比較基準・送信待ち | `ScheduleNotifications` |
| クラス・表示設定 | UserDefaults。設定と時間割で同じ保存キーを使う |
| お気に入り・非表示・色 | `LinkPreferencesStore`。リンクIDに対応する個人設定 |

ファイル種別ごとに現在選択した1ファイルと最後の正常解析を管理します。学校行事APIは年度別に保存します。

## 通常時間割・変更XLSXのDB

`LocalMaterialDatabase` のスキーマは2です。GRDB 7.11.1を固定し、単一の `DatabaseQueue` を使います。外部キーを有効にし、DELETEジャーナル・同期FULLを設定します。既存DBを開く際はapplication ID、スキーマ、ジャーナル方式を確認します。

| テーブル | 役割 |
| --- | --- |
| `source` | ファイルの取得元・アクセス情報 |
| `original` | 原本の識別子・ハッシュ・名前・保存ファイルとの対応 |
| `analysis` | 完成した解析結果・解析器版・補完年度等の入力条件 |
| `lesson` / `changeRow` | 元の順序を持つ授業・変更行。検索項目と保存内容の整合を検証 |
| `attempt` | 取得・解析の直近の成否 |
| `currentRecord` | 現在選択している原本 |
| `currentAnalysis` | 最後の正常解析 |
| `currentLibrary` | 保存世代と既存取得設定 |

同じクラス・曜日・時限に複数授業があっても消さず、解析内の順序で識別します。正常解析は元原本のIDとハッシュに結び付け、新しく選んだ別原本へ付け替えません。DBの `applicability` は `unknown` 固定です。画面への適用日はDBのこの列ではなく、時間割統合処理で判定します。

## 保存と失敗時の保持

1. アクセス権を保持し、取得内容を専用 `staging/` へ読み取ります。サイズ・形式とSHA-256を確認します。
2. 読み取ったファイルをUUIDの管理名で `files/` へ配置します。
3. 原本・取得状態・現在の参照をDBの取引で更新します。保存世代が変わった書き込みは拒否します。
4. 自動解析を実行し、全体の検証が成功してから解析結果と現在の正常解析参照を一括保存します。

取得に失敗した場合は前の選択・コピーを保持します。解析に失敗した場合は新しく選んだ原本と前回の正常解析を保持します。書き込みに失敗した場合は取引を戻し、その処理が配置した未登録ファイルを片付けます。警告付きXLSXプレビューは閲覧専用で、正常結果として保存しません。

試験・返却も、選択原本を解析前に保存し、成功後に正常解析を切り替えます。名称データ・一覧・授業時刻は、公開revisionと取得応答の対応および内容を検証してから保存します。一つの取得失敗でほかの正常結果を取り消しません。

## 初期化と回収

通常資料の新規DBは、隣接する `.initializing` 領域に空DB・原本置き場を作り、閉じたDBを読み直した後に正式領域へ移します。既存DBの欠損・破損・非対応形式では更新を止めます。排他ロックは、別の処理が使用中のstagingを回収することを防ぎます。

現在選択中の原本と正常解析の原本を保持します。参照されない解析行は正常解析の切替時に整理し、通常資料の不要な原本ファイルは次の正常な読み込み時に回収します。試験・返却のstagingと未参照ファイルは専用保存処理が回収します。管理情報を読めないときは回収しません。

旧JSONからの候補作成処理 `LegacyDatabaseMigration` はアプリの起動経路へ接続していません。現行アプリはSQLiteへ保存し、旧JSONへ自動復帰しません。旧領域は[半期削除](private-data-lifecycle.md)の対象です。

## 日付への適用

`TimetableDaySchedule` と `TimetableSchedule` は、通常・変更・試験・返却・行事を組み合わせ、ホームと週表示で同じ規則を使います。

- 通常PDFは年度の前期4月1日〜9月30日、後期10月1日〜翌年3月31日に適用します。学期不明・期間外の授業を流用しません。
- 変更XLSXは年度内の変更一覧です。読み取り成功した全行で正常結果を更新し、日付・クラス・時限に一致する変更を表示へ反映します。
- 試験・返却は各PDFの対象日・クラスを使い、変更XLSXを優先します。
- 日付別時刻は認証APIからの保存結果を使い、試験・返却PDFの検証済み時刻を優先します。
- 学校行事はAPIの保存結果だけを投影します。

元データや解析結果を表示の都合で書き換えません。詳細な優先順位・結合・時刻・行事規則は[時間割の仕様](timetable-tab.md)を参照してください。

## 保護と保存期間

非公開データの保存先は完全ファイル保護とバックアップ除外を設定します。ロック中などで読めない場合は更新確認を見送ります。日本時間の4月1日・10月1日の切替後と初回移行時に、学校由来の非公開データを削除します。削除中は利用を停止し、失敗時は次回に再試行します。公開行事と個人設定は保持します。

通常の失敗時の旧版保持は保存期間内に適用します。削除対象・認証・診断の扱いは[非公開データの管理](private-data-lifecycle.md)を参照してください。

## 検証

架空データでDBの制約、読戻し、保存失敗の巻き戻し、古い保存世代の拒否、原本と解析の対応、回収、期間切替と削除再試行を検証します。例外注入は電源断の再現ではありません。OneDrive・ロック中の保護・容量不足・強制終了後の挙動は実機確認と区別します。結果は[シミュレーター検証](simulator-verification.md)と[検証履歴](verification.md)を参照してください。
