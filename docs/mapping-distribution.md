# 名称データの配信・接続

認証付きの`takupoke-api`から略称と正式名称の対応表を取得します。解析結果はそのまま保存し、通常授業の詳細や時間割変更の表示で照合します。試験・返却PDFの授業名は各PDFの解析結果を使用します。

## 更新確認と認証

公開`GET /mapping-revision`は本文を返さず、ランダムな43文字のrevisionを引用符で囲んだETagを返します。保存値を`If-None-Match`で送り、304なら変更なしです。200の場合も取得した値を保存値と比較します。確認失敗時は前回正常版を保持します。

名称データは起動時に一度確認し、手動操作とバックグラウンド確認でもrevisionを確認します。リンク一覧と授業時刻はアプリ復帰時にも確認します。更新案内はホームと設定の「データ」→「リンク・名称・授業時刻」に表示します。

取得操作では3種類のrevisionを再確認し、必要な更新があれば一回のOIDC認証でリンク一覧・名称データ・授業時刻を取得します。

- `ASWebAuthenticationSession`によるAuthorization Code + PKCE S256。
- `client_id=takupoke-ios`、callbackは`jp.n624.takupoke:/oauth/callback`。
- 要求scopeは`openid mapping.read links.read`。Microsoftの既存SSOを許可します。
- ID Tokenの署名・issuer・audience・nonce・期限を検証し、APIにはAccess Tokenを送ります。Tokenは永続保存しません。

認証後の`GET /mappings/current`はZIPを直接返します。`X-Mapping-Revision`が直前に確認した公開revisionと一致する場合だけ取り込みます。取得中に版が切り替わった場合や認証キャンセル・通信失敗時は旧版を保持します。3種類の保存は独立しています。

## ZIPの検証と保存

ZIP直下の`manifest.json`と`mappings.json`を許可し、CRC・ファイル数・サイズ・schemaVersion・内部バージョン・本文のSHA-256・規則の型と重複を検証します。

- v1：科目・教員・教室の完全一致規則。
- v2：同姓教員を特定する、学校年度・クラス・正式科目名・教員略名の条件付き規則を追加。
- 科目のクラス指定規則を全クラス規則より優先。正規表現による照合は行いません。

形式の詳細は[APIの配布仕様](https://github.com/n624-dev/takupoke-api/blob/main/docs/mapping-package.md)に記載しています。

検証済み規則と公開revisionを専用SQLiteへ一回の取引で保存します。保存成功まで前回正常版を使用します。受信ZIPは一時ファイルで扱い、取り込み後または失敗時に削除します。保存領域にはバックアップ除外とファイル保護を設定します。

## 表示での照合

通常授業ではPDFの略称をカードに、対応表の正式名を詳細に表示します。時間割変更の末尾括弧は、教員・教室の略称と一致したものを抽出します。同姓教員はv2の条件が一意に一致した場合だけ特定し、科目名の括弧や未一致の文字列は残します。

変更カードの短い表記は、正式科目名を介して現在の通常PDFの同じクラスから検索します。候補が一意な場合だけPDFの略称を使用します。留学生向け科目は完全一致規則の対象クラス内で、「留 」を除いた表記にも一致させます。候補の幅判定や表示優先順位は[時間割の仕様](timetable-tab.md)を参照してください。

## 保存期限と出典

サーバーには自動失効期限を設けず、取得時に認証・権限を確認します。iOSは半期切替と保存期間管理への初回移行で対応表を削除します。[非公開データの管理](private-data-lifecycle.md)を参照してください。

配信元は前期・後期の令和8年度時間割と2026年度シラバスを照合して再構築しました。教室・場所は既存対応を引き継ぎ、出典を「令和8年度時間割」と記録しています。教員名・科目の正式名・科目と教員の対応にはシラバスのURLと年度を記録します。シラバスで確認できない「特別活動」「専門演習」はPDFの表記を維持します。

元CSV・確認用CSV・生成ZIPはリポジトリ外で管理します。生成器では配信対象の未レビュー行を拒否し、出典やレビュー状態を生成済みZIPから推測して補いません。公開コード・テストには架空データを使用します。
