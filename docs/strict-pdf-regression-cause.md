# Strict PDF退行の原因調査

394.1公開後、通常・試験・試験返却の解析が戻った利用者の実機報告を受けた。
原PDFは239.1から不変でAI／OCRはOFF。原本・画像・診断本文は取得していない。

## 原因と根拠

239.1以降に追加した表示・Evidenceの証明条件を既定のStrictにも適用し、
以前読めたPDFを拒否するようになった。AI／OCRがOFFでも追加条件を通っていた。
15ce2a2は可視性検査を追加した変更の一つで、42c25a0は背景の描画順・色差・
複合pathの条件を追加した。当時のPDFKitReader.read／readSpecialはそのReaderを直接呼んだ。

| 393.1での実機報告 | 拒否箇所 |
|---|---|
| 通常P12／R265 | ページ内で文字命令が先行した後の背景塗り、stroke付き、細い罫線等 |
| 試験P23／R267 | 文字色と背景明度区間のコントラスト証明が成立しない場合 |
| 返却P12／R270 | 背景のsubpathが一つでない場合 |

R265は見出しや空の文字命令もページ全体のtextSeenへ含める。
R267は位置を区別せず背景を白を含む明度区間へまとめ、別セルや存在しない中間明度まで
対象とする。輪郭付き文字も塗りと線の両方に色差を要求する。
R270は離れた矩形の一括塗りも拒否する。
証明不足をStrict拒否へ広く適用したことが互換性を失わせた。

394.1はReader・字体・座標・罫線・Parserを239.1へ復元し、追加証明は復旧専用へ分離した。
13ソースの逆変換後のbytes一致と今回の実機成功は、追加条件群による退行と整合する。
原PDFの描画命令を調べていないため、複合条件のどの要素に当たったかは未特定。
全条件をまとめて戻したので個別差分の因果寄与も分離できていない。

393.1でも架空PDFの全文比較と全13チェックは成功したが、その入力は実機で拒否された
描画条件の組合せを十分に含めていなかった。比較入力の通過から実資料の受理範囲まで
同じと判断した点が不十分だった。実測は[検証記録](verification.md)、
将来の復旧専用改善は[未実装方針](strict-pdf-regression-plan.md)へ分ける。

## XLSX除外の調査

除外はMaterialSourceと正常解析結果へ保存し、SQLiteもそのpayloadを保持している。
アプリ版番号で削除する処理はない。自動再取得は同一内容なら判断を保持する。
ただし初回selectFileは毎回新しい選択IDを発行し、同一内容の再選択でも除外を消していた。
bookmarkがstaleなら再選択を求めるため、その場合はこの解除経路へ入る。
今回、更新時にbookmarkが失効したか・再選択したかは報告だけでは確定していない。

また旧実装はParser版や年度等の不一致で、再解析成功前に除外を永続的に消していた。
393.1・394.1と除外実装初版のXLSX Parserはすべて6である。
今回のリセットをParser版更新のせいとは扱わない。
通常の再起動保持テストだけでは、旧版の判断の再検証や同一原本の再選択の保持を保証していなかった。
