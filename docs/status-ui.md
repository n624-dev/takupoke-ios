# 設定・ステータス画面

対象は [iOS Issue #183](https://github.com/n624-dev/takupoke-ios/issues/183) の画面と、既存データに基づく表示・操作です。
実装状況と検証結果は [検証記録](verification.md) を参照してください。Issue全体の完了や配布済みを意味しません。

## 設定の入口

既存の設定タブを維持し、標準のListとNavigationLinkで次の6区分に整理します。

| 区分 | 内容 |
| --- | --- |
| ステータス | 要確認件数、確認中、一時停止、未確認などの概要と詳細への入口 |
| データ | 時間割ファイル、学校行事、リンク・名称・授業時刻 |
| 時間割・学習 | クラス、カウントダウン、シラバスの学科 |
| AI・OCR | 使用許可と端末内モデル |
| アプリ設定 | 通知、メインカラー、リンクの開き方 |
| サポート | 初期設定、使い方、このアプリについて |

## ステータスの4区分

- **配信データ**: 学校行事・リンク一覧・名称データ・授業時刻。最終取得や元PDFの確認日時を項目の意味に合わせて表示し、既存の詳細画面へ移動できます。保存済みというだけで最新・認証済みとは表示しません。
- **時間割ファイル**: 通常時間割・時間割変更・試験時間割・試験返却時間割。保存済みの解析結果、取得・解析失敗、中止、未選択を区別します。未選択の任意資料は障害に数えません。除外行数は注意・失敗とは独立した説明です。
- **サービス稼働状況**: Better Stackの公開JSONから、たくポケAPIとたくにんの稼働状況を表示します。両サービスの `/status` から機能別の状態も確認できます。
- **この端末**: ネットワーク経路、取得時の学内認証、自動確認の一時停止、保存データの利用可否。ネットワーク経路があるだけでAPIへ接続できるとは判定しません。

確認できない情報は灰色の未確認にし、色だけでなくアイコンと文言で示します。エラーがあるときは要確認件数を優先します。学校行事では、公式PDFとの照合、配信内容のレビュー、端末の保存版を個別に確認します。元PDFに差異がある場合は「更新待ち」と表示し、保存済みの行事は保持します。

## 公開監視結果の取り扱い

取得先は `https://status.n624.jp/index.json`。認証キー・学内データは送信しません。ページIDは267223、対象の公開リソースIDは9028864（API）と9028865（たくにん）です。
`relationships.resources` と `included` を型・IDで照合し、ページ全体の `aggregate_state` から対象サービスの状態を推測しません。`denpa-schedule-notifier` は対象外です。

利用者が確認した方針は「ステータス画面を表示中は3分ごと」です。ステータス画面とサービス詳細で取得・再確認し、背景移行・最後の画面離脱で通信を止めます。設定トップの概要表示だけでは通信を始めません。親と子の画面が重なる間は同じ取得を共有します。手動更新も可能です。

成功時の本文とETagはメモリに保持します。条件付きGETの304は保存本文と送信ETagがある場合だけ受理し、応答ETagがあれば弱い比較で同一性を確認します。失敗・3分の期限到達・端末時計の逆行では現在の状態を未確認にし、前回取得した履歴は区別して残します。対象サービスが欠落・曖昧な応答では、そのサービスを未確認にし、以前取得した履歴と個別の確認日時を保持します。他の有効なサービスの更新は反映し、304でも欠落したサービスの古い日時は進めません。取得・再確認日時は端末が応答を受けた日時であり、監視の最終probe日時ではありません。ページの更新日時や、Monitorで通常nullの `status_not_updated_since` をprobe日時に転用しません。

日別履歴は返された実際の日付だけを表示します。未監視・未知は灰色、重複する日付は未確認です。稼働率は0〜1の数値だけを割合として受理します。障害報告は対象リソースとの関連を照合し、解決済み判定に `ends_at == null` を使いません。同じ対象の状態が重複する場合は未確認です。更新文は日時順に並べます。

公開監視のJSONは2MiBまで、通信は要求20秒・リソース全体30秒の上限を設定しています。機能別の状態は両サービスの `/status` から取得し、有効期限を過ぎた状態や取得できなかった状態は未確認と表示します。Better Stackは各サービスの `/readyz` を監視します。 [公開ステータスAPI](https://betterstack.com/docs/uptime/status-pages/subscribing-to-status-updates/subscribing-to-api/) · [機能別の状態の仕様](https://github.com/n624-dev/takupoke-api/blob/main/docs/functional-status.md)

## ファイル一覧と詳細

上部にファイル全体の状態と、選択済みファイルの中で最後に更新確認に成功した日時を表示します。全ファイルを一斉に確認した日時とは区別します。一覧は4つの行にまとめ、各行で種類・ファイル名・状態を確認します。選択済み・前回結果がある資料は詳細へ、未選択の資料はファイル選択へ進みます。詳細は状態、ファイル情報、操作、解析結果の順に読み進めます。既存の原本表示・内容訂正・行の除外・復旧・解析結果の授業詳細は維持します。

- 「更新を確認」は選択元を確認し、既存のhash／解析版の規則に従って必要な場合に解析します。
- 「同じファイルを再取得」は同じ選択元から再取得・再解析します。試験・返却でも同じ操作を提供します。
- 「ファイルを選び直す」は標準ファイルピッカーを開きます。古い特殊資料でアクセス権がない場合は再選択を案内します。
- 「処理を中止」は進行中の処理と待機中の要求を中止します。終了が戻るまでは処理中を偽って解除せず、終了待ちを表示します。前回正常結果は保持します。
- メニューの「自動確認を一時停止」は以後の自動確認を止めます。利用者が確認した方針どおり、同じ画面での明示的な再開、または次の起動・前景復帰で再開します。実行中の処理の中止とは別の操作です。

処理段階はファイルごとに表示します。取得元の応答待ち、取得中、解析中、保存中、期限切れや中止後の終了待ちなど、実際に観測した状態を確認できます。 [ファイル取得と解析の期限](materials.md)

## 診断と残る作業

ステータスから固定enumと数値だけの更新確認記録を手動コピーできます。本文・ファイル名・URL・認証情報は含めません。上限と配布検査は [公開情報管理](public-repository.md#更新確認の固定コード記録) に記載しています。

4種類の時間割ファイルの自動確認と手動再取得で、取得・解析の期限、同じファイルの重複防止、保存前の照合を共通化しました。Provider無応答・取得停止・中止後の遅延完了は自動テストで検証しています。OneDriveを使ったiPhone実機での起動・手動再取得の確認は残っています。 [検証記録](verification.md)
