# Strict PDFと端末内復旧の未実装方針

独立した架空PDFを使い、学校原本・原文の値・名前だけを置換した入力は使わない。
Strictは239.1の仕様を基準とし、復旧用の証明不足を新しいStrict拒否条件として足さない。
実装済みの復元経路は[239.1の復元](strict239-restoration.md)へ記載する。

## 復旧専用の取得改善

背景・文字・罫線の範囲、描画順、実際の色と塗り規則を対応づける。
ページ全体のtextSeen、背景色の最小〜最大区間、4.5の色差だけを最終表示の証明にしない。
別セルの背景、白塗りと可視輪郭、空の文字命令、相互に離れた矩形の一括塗りを比較する。
重複・穴・逆向き相殺・上塗り・overprint・未知の合成は、根拠が不足する限りcompleteにしない。
原文の順序・座標・セル所属を保持し、sourceOrderを描画イベント番号へ転用しない。

## 字体・OCR・ローカルAIの比較

字体の意味対応を、対象PDFのcmapや同じ解析コードから作らない独立した信頼済み対照で評価する。
字体SHAや同字体の再描画一致だけではUnicodeの意味を証明しない。
outline照合の同形異義と適用範囲外の拒否条件を固定する。
対象外では元のOCR答えを見せない局所OCR・画像対応ローカルAIを比較する。
OCR同士の一致、辞書、文脈、前回結果を正解の証明にしない。
局所高解像度・重なり付き領域分割・重要見出しの照合は、実際の失敗原因に合うものから比較する。
高信頼の誤読、文書全体、まとまりごとの正読、誤採用を独立した全文正解で評価する。

## 維持する条件

端末内推論だけを使う。資料送信とモデル取得通信を分離する。
取得状態・5状態・Evidence・決定論的Validator・利用者確認・正式保存を分離する。
不明構造を人の入力で埋めず、手動補助は最大3項目。AI結果を自動採用しない。
失敗時は前回正常結果を保持し、バックグラウンドで重いモデルをロードしない。
