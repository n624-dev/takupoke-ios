# Strict PDF解析の互換性を回復する未実装方針

## 比較する範囲

239.1の文字対応・位置・罫線・構造の解析を比較基準にする。
完全に独立した架空PDFを同じ入力で旧版と現行のReaderへ渡し、文書全体の
授業投影まで比較する。文字、位置、セル所属、授業数の一致を検証する。
元の学校PDF、原文の値、原本の名前だけを置換した入力は使わない。

色空間、文字色、罫線色、背景の設定・実使用を一つずつ変え、複合条件と区別する。
可視の色文字・色罫線・背景、未使用の任意色空間、ICCBased／CalRGBなどの対応範囲を調べる。
隠れた文字、同色背景、上塗り、透明、任意表示、切れた文字などを負例として残す。
結果を旧版受理／現行拒否、両者受理、誤採用、実行エラー、未評価に分ける。

## 修正の境界

Strictの既存読取・構造解析と、復旧入力をcompleteとするための証明条件を分ける。
復旧用captureの証明が不足することだけで、従来の読取結果を一律に失敗へ変えない。
ただし証明不足のcaptureを復旧のcomplete入力や正式採用の根拠へ昇格しない。

黒限定を可視性そのものと同一視しない。色の設定と実使用を分け、実際に対応できる
色空間と表示条件を小さく検証する。実表示の確認が必要なら、文字の抽出結果を保持した
局所描画による決定論的検証を比較し、OCR／AIによる値の読み直しでStrictを代替しない。
明示的な不可視・上塗り・破損・不明構造の拒否は維持する。
P23の全解除や共通Readerの全面巻き戻しは行わず、実測で特定した互換性の退行だけを直す。

## 診断と検証

P23の下位原因を、固定の理由コードで区別できるか検討する。
学校由来の文字・数値・色空間名・画像・Promptをログへ出さない。
AI設定OFF／ONともに同じStrict結果で、OFFではOCR・モデル呼出しが0であることを検証する。
対応テストを検索し、可視の色文字まで拒否する期待値は負例の目的を分けて見直す。
隠れた文字の拒否を外さず、旧版で読める架空資料の回帰ケースを追加する。
Parser版と旧失敗キャッシュの再解析も検証する。
配布前の同じコード・実行・試行の全必須検査と、実機の3文書確認を区別する。
