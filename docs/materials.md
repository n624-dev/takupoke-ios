# 学校資料の選択・取得

[README に戻る](../README.md)

通常時間割PDF・時間割変更XLSX・試験PDF・試験返却PDFを iOS の「ファイル」から取得し、学校行事は公開の `takupoke-api` から取得します。取得操作はすべて「設定」→「ファイル選択」にあります。PDF・XLSXは選択後に自動解析し、必要なら解析結果画面から再解析できます。行事APIの結果は年度ごとに端末内へ保存します。試験・返却PDFの新しい読み取り経路は実機での再確認待ちです。

## iPhone で使う

1. OneDrive アプリで学校資料へアクセスできる状態にし、iOS の「ファイル」でも資料を開けることを確認します。「ファイル」に OneDrive が出ない場合は、ブラウズ画面の場所の編集で有効にします。
2. たくポケの「設定」→「ファイル選択」を開きます。
3. 通常時間割・時間割変更・試験時間割・試験返却時間割の各欄から、それぞれPDFまたはXLSXを指定します。用途をファイル名から推測しません。
4. 学校行事は年度を確認して「学校行事を取得」を押します。
5. 各資料の「詳細を見る」で取得日時・自動解析の結果を確認します。必要なときは右上の「解析する」で再解析できます。試験・返却は解析に失敗しても選択状態と前回の正常結果を保持し、全文診断も詳細画面からコピーできます。

「ファイル選択」の各ファイル欄にはファイル名と短い状態だけを表示します。サイズ、取得・確認日時、元ファイルの更新日時、詳しいエラー、通常PDF・XLSXの「同じファイルを再取得」は「詳細を見る」にまとめています。未選択時は詳細リンクを出さず、選択に失敗した理由を一覧に表示します。学校行事の欄には年度入力・取得状態・取得／更新操作を表示し、年度の期間・件数・取得日時と行事一覧は「詳細を見る」で確認します。各詳細画面で授業・変更・行事の数を表す項目名は「件数」に統一します。

利用者の実機では、OneDriveのフォルダを選択できませんでした。現在はすべての資料を個別ファイルとして選び、フォルダ選択と候補一覧の画面はありません。以前フォルダから選んだ資料の保存結果は消さず、保存済みのアクセス情報からの更新を維持します。

## 学校行事APIの保存と更新

取得先は `https://takupoke-api.n624.jp/events?schoolYear=年度` です。APIは現在2026年度を提供し、未公開年度は取得失敗として示します。応答の版、年度、日付、期間、タグ、元PDFのハッシュとETagを確認してから、年度別の保存結果を置き換えます。初回は手動で取得します。次回以降の起動時には保存済み年度だけをAPIのレスポンスETagを使う条件付きGETで確認し、304なら本文なしで保存結果を維持、200なら検証して保存します。ETagを持たない旧保存結果は一度だけ通常のGETで更新します。取得に失敗しても保存済みの結果を残します。

APIのレスポンスETagと `sourcePdfETag` は別の値です。アプリ起動時にはAPIの更新確認後、学校サイトへ元PDFのHEADを送り、APIに記録した取得時の `sourcePdfETag` と比較します。差異や確認失敗を警告し、保存済みの行事は表示します。PDF本文は取得しません。元PDFのETagが同じでもサーバーの実装変更などで本文が同一とは限らないため、厳密なSHA-256確認ではありません。元PDFのETagを持たない旧API結果は再取得の案内を表示します。

旧版で保存した学校行事PDFや解析結果は削除しませんが、時間割には投影しません。学校行事の表示元はAPIのみです。APIのタグを週表示へ反映する規則は[時間割タブの表示仕様](timetable-tab.md)を参照してください。学校のPDF本文やAPIの実データをこのリポジトリ・公開テスト・IPAへ同梱しません。

## OneDriveの初回取得とオフライン設定

選択後に取得できない場合は、「ファイル」で対象ファイルを開いてから再選択してください。OneDriveで「オフラインで使用可能にする」を有効にすると、端末内にファイルを保持できます。

アプリ側は、選択コールバックの時点でURLへのアクセスを開始し、そのアクセスを維持したまま調整された読み取りを行います。成功後に継続アクセス用ブックマークを作成します。以前の「先にブックマークを作って開き直す」順序を変更し、修正版の個別取得と再起動後の再取得に成功したと報告されています。完全な未ダウンロード状態での効果は未確認です。アクセス許可・内容読み取り・ブックマーク保存の失敗は別々の文言で示します。

[Microsoft公式のオフライン利用手順](https://support.microsoft.com/ja-jp/onedrive/read-files-or-folders-offline-in-onedrive-for-ios) では、OneDriveのファイル・フォルダをオフライン指定して閲覧でき、ダウンロード中の状態も確認できるとされています。フォルダ単位にはMicrosoft 365の契約条件があります。また、[Microsoftの「ファイル」連携手順](https://support.microsoft.com/en-us/teams/files/add-third-party-apps-to-the-files-app-on-ios-in-microsoft-teams) はOneDriveを「ファイル」に追加する方法を説明しています。ただし、これらの文書にはオフライン保存が他のアプリへのFile Provider提供まで必ず保証するという説明はありません。オフライン設定によるフォルダ選択の解除も保証していません。

したがって、オフライン設定は取得を安定させる候補として扱います。まず対象ファイルだけをオフライン指定してダウンロード完了を待ち、通常の個別選択と再取得が変わるかを確認できます。必須設定にはせず、フォルダ全体のダウンロードも要求しません。設定の有効化・OneDriveが保持する容量の管理はアプリから行いません。

## 再取得と再選択

- 通常時間割・時間割変更の「同じファイルを再取得」は保存したアクセス情報を使います。学校行事は「学校行事を更新」でAPIの結果を取得します。
- 再起動後もファイルの選択状態は端末から読み込めます。
- 起動時・バックグラウンドから復帰するたびに選択済みファイルをFile Provider経由で読み、SHA-256が変わった資料だけを自動解析します。OneDriveがオフラインなどで読めない場合は確認失敗を表示し、前回の正常結果を保持します。試験・返却PDFは旧選択にブックマークがないため、次に再選択した後から自動確認の対象になります。
- 試験・返却PDFの「最終取得」は選択したコピーを保存した日時です。自動のハッシュ確認に成功すると、内容が同じ場合も「最終確認」を更新します。内容が変わった場合は再取得・再解析し、両方の日時を更新します。
- ファイル移動、アクセス失効、ブックマークの期限切れなどで取得できない場合は、ファイルを再選択します。別のファイルへ推測で切り替えません。
- オフラインで再取得できるかは File Provider の端末内コピーの状態によります。オンライン時と同じ動作は保証しません。

## 制限・失敗時の動作

| 項目 | 現在の仕様 |
| --- | --- |
| 保存対象 | 通常時間割・時間割変更、試験・返却は資料種別ごとに1ファイル。学校行事APIは年度ごとに検証済みの結果を保存 |
| サイズ | 1ファイル50 MiBまで |
| 除外 | シンボリックリンク、Excelの一時ファイル（名前が `~$` で始まるもの） |
| 取得時の形式確認 | 拡張子・空でないこと・PDF / ZIPの先頭識別子。XLSXの構造・内容は別途「保存済みXLSXを解析」で確認 |
| 取得失敗 | 失敗を表示し、前回のコピー・参照先・取得成功日時を保持 |
| 中止 | 中止要求後に処理が戻った時点で終了。File Provider の応答により待つ場合あり |
| 保存情報の破損・コピー欠損 | 更新を停止し、既存ファイルを勝手に消したり初期化したりしない |

「取得済み」は読み取りと保存が成功した意味です。解析成功ではありません。試験・返却PDFを含め、選択した資料と正常な解析結果を分けて保存し、新しい資料の解析失敗後も選択状態と前回の正常結果を表示します。手順と制限は [XLSX解析](xlsx-specification.md#実機での確認手順) を参照してください。

## 保存・一時ファイル・プライバシー

資料のコピー、アクセス用ブックマーク、ファイル名、元の更新日時、取得・確認日時、サイズ、SHA-256、直近の取得結果をアプリ専用の Application Support に保存します。通常資料の解析結果は端末内SQLiteで管理し、行事APIの結果は別の端末内ファイルへ年度ごとに保存します。試験・返却PDFは選択した原本と最後に成功した解析結果を別々に保持します。採用版を保存する統合処理は今後の工程です。

取得途中のファイルは専用の staging に置き、読み取り成功後に保存先へ移動します。管理情報の原子的な書き込みを確定点とし、成功してから古いコピーを削除します。書き込みに失敗した場合は新しいコピーを除去します。途中終了した staging と未参照コピーは、次回「設定」→「ファイル選択」を開いて保存情報を読み込む際に回収します。正常な管理情報を読み取れない場合は削除を行いません。

資料保存ディレクトリはバックアップ対象から除外し、iOS の完全ファイル保護を設定します。端末ロック中の利用は想定しません。元資料は読み取りのみで、アプリから変更・削除しません。File Provider 自身が持つキャッシュは管理対象外です。アプリを削除すると保存したコピーと設定も失われるため、元資料は OneDrive などで保持してください。

学校資料やアクセス情報を開発者のサーバーへ送る処理はありません。OneDrive との通信は File Provider が担当し、行事データの取得時は公開APIへ接続します。画面に表示するファイル名やフォルダ名には学校情報が含まれ得るため、公開 Issue へスクリーンショットを貼る際は伏せてください。エラー表示は固定文言とし、OSエラーに含まれるパスやアカウント情報を表示・ログ出力しません。

## 表示中の変更監視と復帰時の確認

通常時間割PDF・時間割変更XLSX・試験時間割PDF・試験返却時間割PDFが対象です。

- 起動時とバックグラウンドから復帰するたびに、保存済みブックマークを復元し、アクセス権を維持した状態で `NSFileCoordinator` の読み取り内に `NSFilePresenter` を登録します。登録後に元ファイルを読み直します。
- 表示中に内容・属性・移動・削除の通知を受けたら、短時間に届く通知をまとめます。属性通知はダウンロードを伴わないメタデータ参照でファイルの識別子と内容の世代識別子を比較し、両方が前回と同じと確認できた場合だけ読み直しを省きます。識別子が未提供・取得失敗の場合や内容変更・ファイル置き換えの場合は、SHA-256で確認します。取得・解析中に届いた内容変更通知は処理後に確認します。
- アプリ自身のPDF/XLSX読み取りには登録済みのFile Presenterを関連付け、自分の操作に由来する通知を抑制します。ただし実機では関連付けだけでは循環が止まらなかったため、読み取り成功後、ファイルへの協調アクセスが終わる前に、読み終えた内容の世代を比較基準へ記録します。通知のメタデータ取得と比較、成功後の基準更新は同じロックで保護し、古いメタデータを後から基準へ戻さないようにします。失敗・中止した読み取りでは成功時の基準更新を行いません。世代識別子は内容の変更で変わり、拡張属性等のメタデータだけの変更では変わらない値です。更新日時やサイズが同じという理由では、内容が同一とは判定しません。起動時・復帰時の読み直しはこの省略判定の対象外です。
- 元の内容をSHA-256で比較し、変更時だけ既存の解析経路を使います。前回正常結果の保持、失敗表示、試験・返却の解析バージョン更新時の再解析を維持します。
- バックグラウンド移行時に監視を直ちに解除し、登録途中の処理と遅れて届く通知も無効にします。復帰時には再登録・再確認します。別ファイルへの選び直しでも古い監視を解除します。
- 学校行事API・名称対応表の起動時確認は従来どおりです。この変更でAPIの復帰時取得や認証画面の自動表示は追加しません。

取得を安定させるため、OneDriveで対象ファイルの「⋯」をタップし、「オフラインで使用可能にする」を選んで、ダウンロード完了を待ってください。iPhoneの「設定」→「一般」→「Appのバックグラウンド更新」でOneDriveを有効にしてください。低電力モードではバックグラウンド更新が停止し、同期が遅れることがあります。更新が届かない場合は低電力モードを解除してOneDriveを開き、同期状況を確認してからたくポケへ戻ってください。

オフライン指定や調整された読み取りだけで、OneDriveのクラウド上の最新版を強制取得できるわけではありません。File Providerがまだクラウド上の変更を認識していない場合は、同じハッシュの端末内コピーを読み取る可能性があります。通知の即時性や同期の間隔は保証しません。

参照: [AppleのFile PresenterとiOSの注意点](https://developer.apple.com/documentation/foundation/nsfilepresenter)、[登録時のファイル調整](https://developer.apple.com/documentation/foundation/nsfilecoordinator/addfilepresenter(_:))、[Microsoftのオフライン手順](https://support.microsoft.com/ja-jp/onedrive/read-files-or-folders-offline-in-onedrive-for-ios)、[MicrosoftのiOSトラブルシューティング](https://support.microsoft.com/en-us/onedrive/troubleshoot-onedrive-for-ios-app-problems)、[Appleの低電力モード](https://support.apple.com/ja-jp/101604)。


通知の循環対策の参照: [Apple: init(filePresenter:)](https://developer.apple.com/documentation/foundation/nsfilecoordinator/init(filepresenter:))、[内容の世代識別子](https://developer.apple.com/documentation/foundation/urlresourcekey/generationidentifierkey)、[ダウンロードを行わないメタデータ確認](https://developer.apple.com/documentation/foundation/nsfilecoordinator/readingoptions/immediatelyavailablemetadataonly)。


### 更新確認の診断と中止

0.1.102でも実機で処理中→完了の繰り返しが継続したため、世代識別子による対策だけで解消したとは扱いません。内部イベントの順序を調べるため、「ファイル選択」の「更新確認」に常時表示の「更新確認の診断をコピー」を置きます。処理中の行の表示・非表示には依存せず、コピーは自動確認中でも可能です。

診断は起動・復帰、監視登録・解除、内部の内容／属性通知、世代情報の有無、読み取りの開始・同一内容／変更／失敗を記録します。資料種別は固定値だけで、ファイル名・パス・本文・個人名・ブックマーク・ハッシュ値・世代識別子の実値は含めません。起動後の経過時間とイベント番号を使い、開始側と直近を合わせて最大512件だけメモリに保持します。自動送信やディスク保存はしません。コピーは端末内限定で15分後に失効する設定です。

「自動確認を中止」も常時表示します。利用者が中止したときは、実行中の取得・解析へ中止を要求し、待機中の確認と監視も停止します。元の「中止」ボタンも同じ動作です。保存済みの選択・正常結果は保持し、手動の取得・解析は引き続き利用できます。別アプリへ移動して戻ると、監視と確認を再開します。アプリが独断でループを判定して監視を止める処理は追加していません。

0.1.104の実機診断では、4種類とも監視の再登録なしで `metadataChanged → refreshStarted → hashSame` が繰り返されていました。世代情報の取得失敗や再解析の繰り返しではありません。通知時の世代だけを記録して実際の読み取り後の世代を反映していなかった経路を修正しました。診断には読み取り直後の世代記録の成否も固定コードで残します。OneDrive内部でどの操作が世代を変えたかまでは、この診断では断定できません。監視を自動停止する仕様は追加せず、実機での解消を別途確認します。
