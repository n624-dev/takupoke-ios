# 学校資料の選択・取得

[README に戻る](../README.md)

通常時間割PDF・時間割変更XLSX・試験PDF・試験返却PDFを iOS の「ファイル」から取得し、学校行事は公開の `takupoke-api` から取得します。取得操作はすべて「設定」→「ファイル選択」にあります。PDF・XLSXは選択後に自動解析し、必要なら解析結果画面から再解析できます。行事APIの結果は年度ごとに端末内へ保存します。試験・返却PDFの新しい読み取り経路は実機での再確認待ちです。

## iPhone で使う

1. OneDrive アプリで学校資料へアクセスできる状態にし、iOS の「ファイル」でも資料を開けることを確認します。「ファイル」に OneDrive が出ない場合は、ブラウズ画面の場所の編集で有効にします。
2. たくポケの「設定」→「ファイル選択」を開きます。
3. 通常時間割・時間割変更・試験時間割・試験返却時間割の各欄から、それぞれPDFまたはXLSXを指定します。用途をファイル名から推測しません。
4. 学校行事は年度を確認して「行事予定APIから取得」を押します。ファイルを手動で選ぶ必要はありません。
5. 各資料の「詳細を見る」で取得日時・自動解析の結果を確認します。必要なときは右上の「解析する」で再解析できます。試験・返却は解析に失敗しても選択状態と前回の正常結果を保持し、全文診断も詳細画面からコピーできます。

「ファイル選択」の各資料欄にはファイル名と短い状態だけを表示します。サイズ、取得・確認日時、元ファイルの更新日時、詳しいエラー、通常PDF・XLSXの「同じ資料を再取得」は「詳細を見る」にまとめています。未選択時は詳細リンクを出さず、選択に失敗した理由を一覧に表示します。フォルダ内からの候補選択は「フォルダから選ぶ」の欄にあります。学校行事APIは年度・保存件数・取得／更新操作を一覧に置き、取得日時と行事一覧は「詳細を見る」で確認します。

利用者の実機では、フォルダ選択時に OneDrive がグレーアウトし選択できませんでした。OneDriveは個別ファイル選択を基本とします。対応する別のサービスでは「フォルダから選ぶ（対応サービスのみ）」も使えます。直下のPDF・XLSXを一覧にし、サブフォルダは探索しません。

## 学校行事APIの保存と更新

取得先は `https://takupoke-api.n624.jp/events?schoolYear=年度` です。APIは現在2026年度を提供し、未公開年度は取得失敗として示します。応答の版、年度、日付、期間、タグ、元PDFのハッシュとETagを確認してから、年度別の保存結果を置き換えます。初回は手動で取得します。次回以降の起動時には保存済み年度だけをAPIのレスポンスETagを使う条件付きGETで確認し、304なら本文なしで保存結果を維持、200なら検証して保存します。ETagを持たない旧保存結果は一度だけ通常のGETで更新します。取得に失敗しても保存済みの結果を残します。

APIのレスポンスETagと `sourcePdfETag` は別の値です。アプリ起動時にはAPIの更新確認後、学校サイトへ元PDFのHEADを送り、APIに記録した取得時の `sourcePdfETag` と比較します。差異や確認失敗を警告し、保存済みの行事は表示します。PDF本文は取得しません。元PDFのETagが同じでもサーバーの実装変更などで本文が同一とは限らないため、厳密なSHA-256確認ではありません。元PDFのETagを持たない旧API結果は再取得の案内を表示します。

旧版で保存した学校行事PDFや解析結果は削除しませんが、時間割には投影しません。学校行事の表示元はAPIのみです。APIのタグを週表示へ反映する規則は[時間割タブの表示仕様](timetable-tab.md)を参照してください。学校のPDF本文やAPIの実データをこのリポジトリ・公開テスト・IPAへ同梱しません。

## OneDriveの初回取得とオフライン設定

利用者報告では、一度の選択で取得できる資料と、「ファイル」で一度開いた後に取得できる資料がありました。この報告時点では、OneDriveの「オフラインで利用可能」は有効にしていません。未ダウンロード状態やキャッシュの影響は可能性として残りますが、原因は断定していません。

アプリ側は、選択コールバックの時点でURLへのアクセスを開始し、そのアクセスを維持したまま調整された読み取りを行います。成功後に継続アクセス用ブックマークを作成します。以前の「先にブックマークを作って開き直す」順序を変更し、修正版の個別取得と再起動後の再取得に成功したと報告されています。完全な未ダウンロード状態での効果は未確認です。アクセス許可・内容読み取り・ブックマーク保存の失敗は別々の文言で示します。

[Microsoft公式のオフライン利用手順](https://support.microsoft.com/ja-jp/onedrive/read-files-or-folders-offline-in-onedrive-for-ios) では、OneDriveのファイル・フォルダをオフライン指定して閲覧でき、ダウンロード中の状態も確認できるとされています。フォルダ単位にはMicrosoft 365の契約条件があります。また、[Microsoftの「ファイル」連携手順](https://support.microsoft.com/en-us/teams/files/add-third-party-apps-to-the-files-app-on-ios-in-microsoft-teams) はOneDriveを「ファイル」に追加する方法を説明しています。ただし、これらの文書にはオフライン保存が他のアプリへのFile Provider提供まで必ず保証するという説明はありません。オフライン設定によるフォルダ選択の解除も保証していません。

したがって、オフライン設定は取得を安定させる候補として扱います。まず対象ファイルだけをオフライン指定してダウンロード完了を待ち、通常の個別選択と再取得が変わるかを確認できます。必須設定にはせず、フォルダ全体のダウンロードも要求しません。設定の有効化・OneDriveが保持する容量の管理はアプリから行いません。

## 再取得と再選択

- 通常時間割・時間割変更の「同じ資料を再取得」は保存したアクセス情報を使います。学校行事は「行事予定を更新」でAPIの結果を取得します。
- 再起動後も資料の状態は端末から読み込めます。フォルダの候補を再表示するには「フォルダ内の一覧を取得」を押します。
- 起動時には選択済みファイルをFile Provider経由で読み、SHA-256が変わった資料だけを自動解析します。OneDriveがオフラインなどで読めない場合は確認失敗を表示し、前回の正常結果を保持します。試験・返却PDFは旧選択にブックマークがないため、次に再選択した後から起動時確認の対象になります。
- 試験・返却PDFの「最終取得」は選択したコピーを保存した日時です。起動時のハッシュ確認に成功すると、内容が同じ場合も「最終確認」を更新します。内容が変わった場合は再取得・再解析し、両方の日時を更新します。
- フォルダを選び直しても、取得済み資料の参照先は自動変更しません。移行したい資料を新しいフォルダの候補から選び直してください。
- ファイル移動、アクセス失効、ブックマークの期限切れなどで取得できない場合は、資料またはフォルダを再選択します。別の資料へ推測で切り替えません。
- オフラインで再取得できるかは File Provider の端末内コピーの状態によります。オンライン時と同じ動作は保証しません。

## 制限・失敗時の動作

| 項目 | 現在の仕様 |
| --- | --- |
| 保存対象 | 通常時間割・時間割変更、試験・返却は資料種別ごとに1ファイル。学校行事APIは年度ごとに検証済みの結果を保存 |
| サイズ | 1ファイル50 MiBまで |
| フォルダ一覧 | 非表示項目を除き直下1,000項目まで。上限超過は失敗として表示 |
| 除外 | シンボリックリンク、Excelの一時ファイル（名前が `~$` で始まるもの） |
| 取得時の形式確認 | 拡張子・空でないこと・PDF / ZIPの先頭識別子。XLSXの構造・内容は別途「保存済みXLSXを解析」で確認 |
| 取得失敗 | 失敗を表示し、前回のコピー・参照先・取得成功日時を保持 |
| 中止 | 中止要求後に処理が戻った時点で終了。File Provider の応答により待つ場合あり |
| 保存情報の破損・コピー欠損 | 更新を停止し、既存ファイルを勝手に消したり初期化したりしない |

「取得済み」は読み取りと保存が成功した意味です。解析成功ではありません。試験・返却PDFを含め、選択した資料と正常な解析結果を分けて保存し、新しい資料の解析失敗後も選択状態と前回の正常結果を表示します。手順と制限は [XLSX解析](xlsx-specification.md#実機での確認手順) を参照してください。

## 保存・一時ファイル・プライバシー

資料のコピー、アクセス用ブックマーク、ファイル名、元の更新日時、取得・確認日時、サイズ、SHA-256、直近の取得結果をアプリ専用の Application Support に保存します。通常資料の解析結果は端末内SQLiteで管理し、行事APIの結果は別の端末内ファイルへ年度ごとに保存します。試験・返却PDFは選択した原本と最後に成功した解析結果を別々に保持します。採用版を保存する統合処理は今後の工程です。

取得途中のファイルは専用の staging に置き、読み取り成功後に保存先へ移動します。管理情報の原子的な書き込みを確定点とし、成功してから古いコピーを削除します。書き込みに失敗した場合は新しいコピーを除去します。途中終了した staging と未参照コピーは、次回「設定」→「ファイル選択」を開いて保存情報を読み込む際に回収します。正常な管理情報を読み取れない場合は削除を行いません。

資料保存ディレクトリはバックアップ対象から除外し、iOS の完全ファイル保護を設定します。端末ロック中の利用は想定しません。元資料は読み取りのみで、アプリから変更・削除しません。File Provider 自身が持つキャッシュは管理対象外です。アプリを削除すると保存したコピーと設定も失われるため、元資料は OneDrive などで保持してください。

学校資料やアクセス情報を開発者のサーバーへ送る処理はありません。OneDrive との通信は File Provider が担当し、行事データの取得時は公開APIへ接続します。画面に表示するファイル名やフォルダ名には学校情報が含まれ得るため、公開 Issue へスクリーンショットを貼る際は伏せてください。エラー表示は固定文言とし、OSエラーに含まれるパスやアカウント情報を表示・ログ出力しません。

## 実機確認項目

チェック済みは利用者から成功報告があった項目です。未チェックは確認待ちです。公開の報告にはファイル名・学校名・内容を記載せず、成否と一般的なエラーだけを残します。

- [x] 旧版でOneDriveのフォルダは選べず、個別ファイルは一度開けば取得できる（利用者報告）。
- [x] 修正版で通常時間割PDF・変更XLSXを個別に取得できる（取得前のダウンロード状態は未記録）。
- [x] 旧版の学校行事PDFを学校サイトから取得でき、再起動しても保持される（過去版の報告）。
- [ ] 学校行事APIを取得・更新でき、再起動後も年度別の結果が残る。
- [ ] 学校行事APIの通信失敗・中止後に以前の保存状態が残る。
- [ ] 起動時に行事APIの304で本文を受け取らず、200の更新では新結果を保存することを実機で確認する。
- [ ] 起動時の行事元PDFのETag警告と、オフライン時の確認失敗表示を実機で確認する。
- [ ] 選択済みPDF・XLSXの変更時だけ自動解析し、読み取り失敗時に前回結果が残ることを実機で確認する。
- [ ] 必要ならOneDriveの対象ファイルだけオフライン指定し、取得成功率・通信オフでの再取得を比較する（現在は未設定）。
- [x] アプリ終了・再起動後に3資料の保存状態が残る。
- [x] 再起動後に個別資料の「同じ資料を再取得」が成功する（PDFかXLSXの少なくとも一方。両方それぞれの結果は未記録）。
- [ ] OneDrive 側で資料を更新して再取得すると、取得日時と元の更新日時が反映される。
- [ ] 未ダウンロードの資料がオンラインで取得できる。
- [ ] オフライン・アクセス失効・元資料の移動時に、取得できなければエラーと前回の資料が残る。
- [ ] 資料を選び直して取得に成功すると、失敗表示が解消する。
- [ ] 中止後に再試行でき、前回の資料が保持される。
- [ ] 次のアプリ更新後も、資料の選択状態と保存情報が残る。
