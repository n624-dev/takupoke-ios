# 通知とバックグラウンド確認

## 通知

初期設定の「はじめる」でiOSの通知許可を求めます。許可すると、時間割変更と試験・返却の通知を有効にします。「あとで設定」を選んだ場合は、設定の「アプリ設定」→「通知」から有効にできます。通知の種類は個別に切り替えられます。

すでに初期設定を済ませている場合は、更新後に「設定」→「アプリ設定」→「通知」で必要な種類を有効にしてください。初期設定を再び開いても、保存済みの通知設定は保持します。

- 時間割変更：今日以降で、時間割の選択中クラスに関係する変更を通知します。追加・変更・削除を比較し、同じ日付・クラス・時限の更新を1件として数えます。
- 試験・返却：選択済みPDFの内容が変わり、その内容の解析に成功した場合に通知します。新しいPDFは「時間割ファイル」で追加できます。
- 初回取り込みは比較用の基準として保存します。その後の差分が通知の対象です。並び替え、同じ内容の再取得、クラス選択だけの変更では通知しません。
- 通知には種類と件数を表示します。内容はアプリで確認できます。

比較の基準はクラス・日付・時限と内容のハッシュ、試験・返却PDFのハッシュです。端末内のファイル保護された保存先に置き、4月1日・10月1日の切替時に学校データと一緒に削除します。通知センター内の通知も削除します。通知設定は保持します。

通知を両方OFFにしている間も比較用の基準を更新します。通知画面ではOFF中の許可確認を省き、有効にする操作でiOSの許可を求めます。ONにしている種類がある場合は、iOSの現在の許可状態を確認します。

送信待ちの通知も比較基準と一緒に保存します。送信が中断された場合は次の確認で再試行し、通知センターの受け付け済み通知と照合して同じ更新の重複送信を抑えます。

## バックグラウンド確認

アプリが背景へ移ったとき、iOSへ更新確認を登録します。確認対象は次のとおりです。

- 選択済みの通常時間割PDF・時間割変更XLSX・試験PDF・返却PDF。内容のハッシュが変わった場合に解析します。
- 保存済み年度の学校行事API。ETag付きの条件付きGETで取得します。
- リンク一覧・名称データ・授業時刻の公開更新識別子。更新を検知した場合はホームと設定で案内し、新版は利用者の認証後に取得します。

保存データを読めるときに確認します。ロック中でデータ保護が有効な場合は見送ります。取得失敗・中断・解析失敗時には、保存期間内の前回正常結果を保持します。

実行時刻はiOSが決定します。次の実行を要求する最短時刻は1時間後ですが、1時間ごとの実行を意味しません。低電力モード、Appのバックグラウンド更新、アプリの強制終了なども実行に影響します。OneDrive側の同期状況により、読み取れるファイルの版も異なります。

起動・復帰時の確認は継続します。起動時の学校行事元PDFのHEAD確認と、バックグラウンドでの行事API確認は別の処理です。

## アクセシビリティ

時間割カードと今日の予定は、省略前の科目・教員・教室・時刻をVoiceOverへ渡します。時間割カードには日付・クラス・時限、変更カードには変更の種類も含めます。日付見出しと週選択は月日として読み上げます。OSの文字サイズに応じたグリッドの拡大は[時間割の表示仕様](timetable-tab.md#osの文字サイズ)に従います。

## 検証

差分判定は架空のデータで検証します。実機では通知許可・初回取り込み・選択中クラスの変更通知・試験／返却PDFの更新通知・バックグラウンド確認・VoiceOverを確認してください。iOSによるバックグラウンド実行頻度は、ビルドや自動テストの成功だけでは確認できません。

参照：[Appleの通知許可](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications)、[SwiftUIのバックグラウンドタスク](https://developer.apple.com/videos/play/wwdc2022/10142/)、[BGAppRefreshTask](https://developer.apple.com/documentation/backgroundtasks/bgapprefreshtask)。
