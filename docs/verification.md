## XLSX解析のSwift実装（2026-09-19）

このLinuxデバイスのSwift 6.1.2で確認した範囲は次のとおりです。

- 固定したPython参照結果9ケースを圧縮XLSXに変換し、inline strings / shared stringsの両形式で読み取る。通常7ケースは10フィールドの一致、境界2ケースは意図的な拒否を確認。

利用者から通常時間割の本文なし診断を受け取り、文字を仮の記号に置き換えた非公開の再現処理でP20が発生することを確認しました。診断にはセル幅を超える文字の矩形があり、別の文字列の範囲を包含していました。従来は `PDFSelection.bounds(for:)` の選択矩形を文字の位置として使っていたため、過大な矩形の中心がセル内に入ると、その文字列を当該セルに取り込む構造になっていました。実機の選択矩形に問題があることは確認できましたが、修正後のPDFKit実行はまだ確認していません。

通常時間割の解析バージョン6では `PDFPage.characterBounds(at:)` で同じUTF-16範囲の文字単位の矩形を取得します。ページ文字列と選択文字列の一致、ネイティブの行と読み順、ページ回転の処理は維持します。合成文字は範囲内の矩形をまとめ、空・無効・無限の矩形や範囲外アクセスは拒否します。セルの境界や包含・逆順の判定条件は緩和していません。学校行事は従来の選択矩形を使う経路と解析バージョン4を維持します。

- Linux / Swift 6.1.2の架空データによる解析テスト38件が通過。独立した架空の隣接セルで、過大な選択矩形によるP20と、文字単位の矩形で正しい科目・教員・教室が取得できることを検証しました。UTF-16合成文字の範囲、無効な範囲・矩形の拒否も確認しています。
