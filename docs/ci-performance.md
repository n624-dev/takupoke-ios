# CIの実行時間

アプリUIはiOS 26・27で検証し、配布ビルドと公開を同じRunnerで行います。処理の実行順とテストの準備を改善し、必要な検証を維持したまま所要時間を短縮します。

## 計測

`tools/timed_command.py`が各処理の開始・終了と経過秒数を出力します。対象はテスト用プロジェクト生成、シミュレーター起動、UI検証、保存・取得の検証用コンパイルと実行、Swiftパッケージのテスト、iPhone向けReleaseビルドです。ReleaseビルドはXcodeのBuild Timing Summaryも出力します。

ファイル選択UIとホストテスト・ビルドは`tools/parallel_build.py`で並列実行し、処理名を付けたログを実行中に出力します。中止・失敗時には起動したプロセス群を停止し、各処理の一時ファイルを片付けます。

## 実行順と公開条件

配布テストの成功後、iOS 26 UI、iOS 27 UI、配布ビルドを同時に開始します。IPAは公開までRunner内に保持します。

`tools/release_gate.py`は、現在の実行ID・再実行回・コミットに対応する配布テストと両OSのUI検証を確認します。公開ジョブ自身の完了は待ちません。必要なジョブの失敗・中止・スキップ、異なるコミットや再実行回、重複ジョブ、APIエラーを検出した場合は停止します。未完了・未登録のジョブは60秒間隔で最大40分待ち、時間切れなら停止します。mainのコミットと公開物の照合は公開処理でも行います。

UIテストは最初から各テストに必要な条件で起動します。文字サイズ・空データ・更新・取得失敗の確認で、標準条件のアプリを起動してから直ちに起動し直す処理を省きます。設定の保存や通知の差分確認に必要な再起動はテストに含めます。
