# Strict PDFの互換性修正

## R126の塗り矩形とエラー表示の修正

[392.1](https://github.com/n624-dev/takupoke-ios/releases/tag/v0.1.392-build.392.1)へ公開した。source8219fa5の全13検査と匿名添付照合は成功。
更新後も実資料のP12／R126が継続する報告があり、復旧していない。具体的な検証は[検証記録](verification.md)を参照する。

罫線として使える太さの条件を、塗り矩形自体の許可条件から分離した。
閉じた軸平行矩形の角・辺、可視色、全取得文字との非重複を確認できる装飾は、幅広でも許可する。
装飾の検証には原文字の非空の範囲を必須とし、それがない単独スキャンでは従来どおり拒否する。
細い矩形だけを従来の条件で罫線へ変換し、広い装飾をセル境界へ使わない。
前後の描画順で遮蔽の判定を回避せず、輪郭文字の実描画範囲との衝突も既存経路で拒否する。
非矩形・透明・未知状態・clip・文書全体の構造・日付／授業の対応検証は維持した。
通常Parser版30・試験／返却27へ更新し、同じSHAの旧失敗を再解析する。

通常・試験・返却のエラー説明とコード／ページを共通の別表示要素にした。
「確認箇所：塗り図形」などの内部分類は画面に出さず、保存されたstage・cell・branchは保持する。
文字列の改行で配置を作らず、自然な折り返しと標準のアクセシビリティを使う。

独立した元9PDFは変更せず、装飾を前後に描く18派生を追加し、全3Parserで同じ正解と照合する。
塗りが実際に文字へ重なる拒否対照と、小さい／幅広の装飾による原文・罫線の不変も検証する。
元の「文字から離れた幅広の塗りを必ず拒否」という期待は今回変更する仕様に対応しており、
重なりの拒否期待へ置き換え、非重複の旧入力は成功対照へ移した。
実測・CI・公開と実資料の確認は[検証記録](verification.md)へ分けて記録する。
P12／R126報告だけでは角・辺・重なりの実原因は未特定であり、実機復旧を保証しない。

基準は239.1（bfc599fd5a552ced0c140497c703199547c30fd4）。
380.1・今回の解析・AI／OCR OFFで通常P01、試験と返却P12が継続した報告に対応する。
全文差分は[固定コミットの監査](strict-pdf-diff-audit-239-380.md)へ残す。
実資料の実際の拒否分岐は未特定であり、以下を実機解消済みとは扱わない。

## 修正範囲

- Tr 1／2の一律拒否を撤回。元のUnicode・文字順・座標を保持し、
  埋め込みTrueTypeのPDFコード→GIDが明示できる場合は実glyphのpath境界、
  その他はFontBBoxと変換後の線幅、join／miterから別の描画範囲を作る。
  その範囲もページ・clipに入ること、罫線・塗り図形と重ならないことを確認する。
  描画範囲を証明できない字体、太い／破線の輪郭、不可視色、Tr 3〜7は受理しない。
  Tr2の白fillは、全glyphの字体範囲が分かり、他のglyphと重ならない場合だけ認める。
- Normalブレンドの単独名と1要素配列を同じ意味として扱う。
  代替が混在した配列や未知のブレンドは許可しない。
- 曲線は設定時の一律拒否をやめ、nで破棄された場合を許可する。
  実際に曲線を描いた場合の拒否を維持する。
- 有効な破線設定は保存・復元し、塗り文字に使わず上書きされた場合を許可する。
  破線を罫線や輪郭文字として採用しない。
- 幹が一意で文字と重ならない塗り矢印を、従来の検出器へ通す。
  任意の三角形や幅広の塗りは許可しない。
- Parser版を通常29・特別26に更新し、同じ内容SHAの旧失敗も再解析する。

## 維持する条件

ToUnicodeとPDFKit文字の照合、原文行・順序・セル所属、文書全体の構造検証、
年度の矛盾、日付・時刻の対応、空欄の役割と並記の曖昧性への拒否は維持する。
これらを外すと読めた文字を別の授業へ誤って割り当てる場合があるためである。
OCR／AIの呼び出し、確認UI、保存・取得、バックグラウンドの挙動は変更しない。

## 比較と確認

通常1ページ・試験6ページ・返却1ページを、それぞれ独立した架空の設計から生成する。
各設計にTr 0／1／2の3表現を用意する（3設計・9PDF・24ページ）。
輪郭の表現にはNormal配列、破棄される曲線、未使用の破線も含める。
元資料を入力・模倣せず、科目・教員・教室は明示的な架空値にする。
学校への通信はなく、生成器が取得するのはSHA固定の公開フォントだけである。

同じ生成PDFと同じ検査を239.1と現行のReader→Parserで実行し、
クラス・曜日／日付・時限・科目・教員・教室・授業数・時刻まで独立した正解と照合する。
古いコードへ追加するのは比較用テストの登録だけで、製品の解析条件は変えない。
現行では既存の不可視・重なり・破線・clip・曖昧なセルの拒否検査も実行する。
生成PDF・フォント・旧版の作業コピー・ビルドは所有する一時領域内で削除し、
Actions保存用artifactやキャッシュへ残さない。

CI成功と実機の3資料の改善は分けて記録する。
実行結果・失敗・対応根拠は[検証記録](verification.md)と[改善記録](ocr-improvement-log.md)へ残す。

両SDK比較は[38331543392](https://github.com/n624-dev/takupoke-ios/actions/runs/38331543392)で成功した。
239.1と修正版の同じ9PDFが全解析・独立正解と一致し、現行548件は予定skip1・失敗0。
公開前の全必須検査と実資料の実機復旧はこの比較から完了扱いにしない。

## 2026-10-14 背景の描画順を区別する追加修正（検証中）

392.1への更新後も利用者の3PDFでP12／R126が継続した。原本は不変でAI／OCR OFFの
既報を保持する。前回の非重複装飾への限定修正では実機の問題を解消していない。

現行Readerは全原文字の箱との重なりを、文字描画の前後を問わず拒否していた。
239.1は幅広い塗りを罫線として使わず無視した。今回、原文字の範囲が既知で、全文字より前に
描かれた軸平行の幅広い不透明な塗り矩形だけを背景候補として区別する。単一矩形pathへ限定し、複合fillの穴や相殺はR270で拒否する。
単色プローブに含まれない有効／未知のoverprintは新背景の許可へ使わずR271で拒否する。
背景後の文字・罫線等にも適用し、q／Q復元と明示falseを保持する。
細い罫線・線付き図形・最初の文字より後の重なりは許可しない。

背景色と全後続文字・罫線・矢印等の色はQuartzによる小さい単色描画の実測値を使う。
グレースケール値を線形化し、背景値と未被覆部の白面を含む最小〜最大の間の最近点に対して比4.5以上を要求する。
位置ごとの背景推定はしないため、複数の背景がある場合も保守的に拒否できる。
色が不明・同色・低コントラスト・透明・後の上塗り・不明なclipは拒否する。
これを文字の意味・字体対応・セル所属の証明には使わず、既存の抽出／構造検査を維持する。

R126は四隅の検査へ限定し、旧番号の復元を保持する。辺はR263、原文字範囲の不足はR264、
重なりの描画順／薄線／線付き条件はR265、背景色はR266、文字との色の差はR267で識別する。
既存の罫線を背景で消す順序はR268、背景と罫線・矢印等が同色／低コントラストならR269で拒否する。
通常Parser31・試験／返却28とし、同じSHAの旧失敗も再解析する。行事4・XLSX6は変更しない。
エラーUI、AI／OCR、正式保存、UIテスト・Runner・配布ゲートは変更しない。

独立した3文書設計の既存27表現・72ページを保持し、各描画モードに背景付き表現を追加する。
合計36表現・96ページは3つの独立設計であり、36種類の学校書式の成功率とは扱わない。
239.1と修正版へ同じ入力と固定した文書全体の期待値を渡す。
Reader検査には塗り／輪郭／両方の3モード、後塗り、同色、低コントラスト、薄線、透明を追加する。
実資料の残るR126条件が背景の重なりだったかは未確定であり、今回も実機確認とCIを分ける。
