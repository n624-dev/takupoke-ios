# 時間割変更XLSXの移植仕様

[READMEに戻る](../README.md)

ロードマップ③としてSwiftのXLSX読み取り・正規化・結果確認画面を実装しました。固定した既存Python実装の期待結果と架空データで比較しています。**iOSビルド・実機の解析結果は確認待ちです。PDF解析・通常時間割への統合は未実装です。**

## 参照実装

参照元はMITライセンスの [denpa-schedule-csv / excel_to_class_schedule_csvs.py](https://github.com/n624-dev/denpa-schedule-csv/blob/ba3db92dddd8b453348e5a78b5d716a10ee72145/excel_to_class_schedule_csvs.py) です。コミットは `ba3db92dddd8b453348e5a78b5d716a10ee72145`、ファイルのSHA-256は `7bbbbca774f40623ee6fbd9c227a68e8bd675ae3fcdf6a0415cfd67a00513f90` です。ローカルの配置済みコードと開発用checkoutで本体が一致することを確認しました。学校資料や変換出力は比較データの作成に使用していません。

以下はこの版のコードから確認した動作です。将来の参照元の変更を自動で取り込みません。CLIによるCSV出力・ZIP配布はiOSへの移植対象外です。

## XLSXから表を読む規則

- `xl/workbook.xml` とそのrelationshipsからシートを特定する。変換APIの標準は `時間割変更` の厳密指定。iOSでも別シートへ推測で切り替えない。
- shared stringsとinline stringsは、リッチテキスト内の各 `t` を連結する。数値は文字列、真偽値は `TRUE` / `FALSE` として読む。
- セル参照の列番号で欠落セルを空文字で補う。結合セルの値は展開しない。数式を計算せず、保存された値を読む。
- 正規化後の `学 年`、`学科・クラス`、`月日` をすべて含む最初の行を見出しにする。それより前は表に含めない。
- 見出しは文字列正規化する。ただし正規化すると `時限` になる見出しは元の表記を保持する。
- データ行は見出しの列数まで空欄補完・切り詰めを行い、完全な空行を除外する。整数相当の小数表記は整数文字列へ変換し、月日のExcelシリアル値を日付文字列へ変える。

## 正規化・展開

| 対象 | 参照実装の規則 |
| --- | --- |
| 文字列 | NFKC、CRLF / CRをLFへ統一、連続した横方向空白を半角空白1つへ、連続LFを1つへ、前後空白除去 |
| 列名・クラスの照合 | 上記に加え半角空白除去・大文字化 |
| 数値文字列 | `1.0` → `1`、`-2.00` → `-2`。それ以外は正規化した文字列を保持 |
| Excel日付 | 正の数値を1899-12-30起点の日数として変換。小数部分も日数に含める |
| 日付文字列 | 年月日、スラッシュ、ハイフン、ドット区切りを処理し、認識できたものは `YYYY-MM-DD` |
| 年のない日付 | `default_year` を使用。省略時は実行時の年（iOSでは下記の追加検証が必要） |
| 学年 | `1～3`、`1〜3`、`1~3`、`1-3` を両端を含めて展開。逆順の指定もその順序で展開 |
| 複数クラス | 半角・全角カンマ、読点で分割。入力順を維持し、重複を自動除去しない |
| 「全」 | 入力全体から同じ学年に明示されたクラスを集めてソートし、`AI` を除いて展開。全校のクラス一覧を仮定しない |
| 明示のAI | `AI` を直接指定した行は対象に含める |
| クラス識別子 | `学年_クラス`。学年かクラスが空なら出力しない |
| 時限 | 末尾の `時限` / `限目` / `限` を除き整数表記を正規化。`1,2` は1文字列のまま |
| 出力順 | 入力行 → 展開した学年 → 展開したクラス。レコードの重複を除去しない |

`全` しかなく同学年のクラスを特定できない場合、参照実装の出力は0件です。Swiftでは対象を確定できない行として解析を停止し、前回の正常結果を保持します。

## 列の別名と変更前後科目

同じ用途の列が複数ある場合、参照実装は**入力の見出し順**で最初に一致した列を選びます。最初の値が空でも後の列に進みません。次の表の記載順は優先順位ではありません。

| 出力 | 対応する列名 |
| --- | --- |
| period | 時限、校時、時間、限 |
| before_subject | 変更前、変更前科目、変更前 科目、旧科目、変更元 |
| after_subject | 変更後、変更後科目、変更後 科目、新科目、変更先 |
| teacher | 教員、担当、担当教員、担任、教官 |
| room | 教室、場所 |
| note | 備考、連絡、メモ、その他 |

補助列 `変更内容` / `変更種別` / `種別` の値があり、備考が空なら、その値を備考へ入れます。`科目(担当教員)` / `科目（担当教員）` / `科目・担当教員` / `科目` は、変更前後のいずれも空の場合だけ使います。変更内容が `休講` なら変更前に、それ以外なら変更後に入れます。明示された変更前後の一方だけが入っている場合も、もう一方を推測で補いません。

科目と教員の併記はそのまま保持し、括弧を分解して教員名を推測しません。`teacher` は教員用の列からのみ取り出します。

出力は `change_date, class_name, period, before_subject, after_subject, teacher, room, note, raw_text, canonical_text` の10項目です。`raw_text` は非空の値を見出し順に `見出し:値` として ` | ` で結合します。`canonical_text` は先頭9項目の非空値を正規化して同じ区切りで結合します。これらには実資料の内容が含まれるため、アプリの公開ログには出しません。

## 互換性とiOSでの追加検証

参照実装は暦に存在しない日付も文字列として整形し、認識できない日付は元の値を返します。また1904年起点の日付設定を見ていません。Swiftでは有効な日付、日付起点、必須列・セル型を検証し、未対応や曖昧な入力で正常結果を置き換えません。年なし日付は利用者が指定した西暦を使い、解析結果に保存します。指定がなければ解析を停止します。年度ではなく西暦の指定であり、1〜3月を翌年へ自動変更しません。

次の差異は誤った解析結果への置き換えを避けるための意図的な制限です。

- 不正な暦日、年を確定できない日付、空の学年・クラス、不明な「全」、完全に空の結果は失敗とする。
- 学年は1〜9、クラスは正規化後の英大文字・数字1〜12文字、西暦は1900〜9999に限定する。
- 完全一致する非空の見出し重複、同一セルの重複、値要素などの重複、見出しより右の非空セル、不正なshared string参照は拒否する。別名の異なる列は参照実装どおり見出し順で選ぶ。
- 1904年起点、数式（保存値があっても不可）、見出し行以降の結合セル、外部参照、マクロ付き資料は未対応として拒否する。見出しより上のタイトル結合は許容する。
- UTF-8の標準OOXML名前空間に対応する。UTF-16、Strict OOXML、DTD・エンティティ宣言は未対応。
- リッチテキストのふりがな `rPh` は表示値に加えない。参照実装は子孫の `t` をすべて連結するため、この点は異なる。架空のふりがな付きセルでSwift側の表示値を検証する。

ZIPFoundation 0.9.20のコミット `22787ffb59de99e5dc1fbfe80b19c97a904ad48d` を固定して使います。[公式の読み取りAPI](https://github.com/weichsel/ZIPFoundation/blob/22787ffb59de99e5dc1fbfe80b19c97a904ad48d/Sources/ZIPFoundation/Archive%2BReading.swift) のストリーム受信で上限を確認し、戻されたCRCと記録されたCRCを照合します。展開先ファイルを作らず、必要なXMLだけをメモリーへ読みます。XMLParserの外部エンティティ解決は無効とし、取得先URLを辿る処理はありません。

| 上限 | 値 |
| --- | --- |
| 元XLSX | 50 MiB |
| ZIP項目数 | 2,048 |
| ZIP内の申告展開サイズ | 1項目32 MiB、全体64 MiB |
| 読み取るXML | 1文書8 MiB（申告値と受信量の両方で確認） |
| XML構造 | 1文書200,000要素、深さ64 |
| ワークシート | 行番号10,000まで、列DX（128列）まで、セル100,000個 |
| 文字列 | 1セル／文字列4,096 UTF-8バイト、shared strings 50,000個、参照展開後の全セル合計16 MiB |
| 展開後の結果 | 20,000件、全フィールド文字列の合計16 MiB |

解析は資料取得と同じ直列キューで実行し、取得と同時に保存済みXLSXを差し替えません。すべての行の解析・検証が成功してから、取得管理JSONを原子的に更新します。一部の行だけを正常結果として保存しません。書き込み失敗時はメモリー上・ディスク上の前回結果を維持します。

取得済み資料のSHA-256と解析時のSHA-256が異なる場合、画面に「前回の解析結果」と表示します。新しいXLSXの取得だけでは前回の解析結果を消しません。正常結果とともに元資料名、SHA-256、補完年、解析バージョン、解析成功日時を保存し、直近の解析失敗は別に管理します。空の資料からの変更全削除や、正常な時間割への統合はこの段階では行いません。

## 架空の比較データ

[normalization.json](../tests/fixtures/normalization.json) は実資料を参照せず作成した表と、固定した参照実装で生成した期待結果です。教師名・教科名・教室・自由記述には `架空教員A`、`架空科目A`、`架空教室A`、`架空備考A` などを使います。`AI`、`全`、列名、変更種別はパーサーの規則を検証する識別子です。

文字の正規化、日付、学年範囲、複数クラス、「全」とAI、休講・補講・変更、明示科目の優先、別名の選択順、空行を含めます。`iosDisposition: requiresValidation` は参照実装の現状を記録する境界例であり、iOSで正常データとして受理する期待値ではありません。

期待結果は次のコマンドで再生成・照合できます。固定版のPythonファイルを別途ローカルに用意してください。学校資料の指定、ネットワークアクセス、参照実装のCLI実行は不要です。

```sh
python3 -B tools/generate-normalization-fixtures.py --reference /path/to/excel_to_class_schedule_csvs.py --check
# 架空入力を意図的に変更した後だけ、--checkを外して期待結果を更新する。
```

Windowsでは `python3` を `py -3` に置き換えます。SHA-256が違う参照コードは実行前に拒否します。この補助ツールはCIから実行せず、Swift比較テストはリポジトリ内の期待結果を直接使います。`bash tools/test-parsing.sh` では9ケースをinline strings / shared stringsの両形式の圧縮XLSXへ変換し、読み取りから正規化まで通して7ケースの全フィールド一致と2ケースの意図的な拒否を確認します。架空XLSX・ビルド・依存checkoutは終了時に削除します。実際の教師名・教科名は一切使用しません。


## 実機での確認手順

1. AltStoreから更新し、「学校資料を選ぶ」→時間割変更の「XLSXを解析・結果を確認」を開く。
2. 年のない日付を含む資料では、資料が対象とする**西暦**を入力する。年が明記されている資料なら空欄でもよい。
3. 「保存済みXLSXを解析」を押し、件数が表示されることを確認する。
4. 自分のクラスを選び、手元の資料と日付・時限・変更前後科目・教員・教室・備考を照合する。併記された教員を専用の教員欄に推測で分離していないことにも注意する。
5. アプリを終了・再起動し、解析結果と補完年が残ることを確認する。
6. 年なし日付がある場合だけ、補完年を空欄にして再解析し、エラーが表示されても前回の正常結果が残ることを確認する。確認後は正しい年を入れて再解析する。

報告は成否、件数、一般的なエラー文・行番号で十分です。実際の教師名・教科名、資料名、結果画面全体や資料そのものを公開Issueへ貼らないでください。未対応のエラーが出た場合は、推測で反映する範囲を広げず、非公開の状況確認と架空の再現データで対応を検討します。
