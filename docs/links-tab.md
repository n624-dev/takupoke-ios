# 一覧タブの仕様

`takupoke-astro` と一覧リンクデータを、iOS版ではSwiftUIで表示します。iOSのタブ順は「ホーム → 一覧 → 時間割 → 設定」です。Web画面は埋め込みません。

ホームには一覧と同じお気に入りリンクを同じ順序で表示します。色・非表示・お気に入りの変更は共有し、リンクの開き方も同じ設定を使います。保存済み一覧がない場合や、お気に入りがない場合はリンクを表示しません。

## データと更新

- `GET https://takupoke-api.n624.jp/links` は全リンクでBearer認証が必要です。配信元の `visible: false` のリンクはAPI応答に含めません。
- 起動・復帰・一覧を開いたときは公開 `/links-revision` で本文なしのランダムrevisionを確認します。保存値を `If-None-Match` に送り、一致は304、不一致は200です。更新を検知しても保存済み一覧は消しません。
- 利用者が取得・更新を押すと、一覧と名称対応表のrevisionを確認します。必要な更新があれば一回のOIDC認証（`openid mapping.read links.read`）で両方の取得権限を得ます。引き下げ更新もこの共通処理です。トークンは永続保存しません。
- 取得した一覧の `X-Links-Revision` が確認した値と一致すること、JSON形式・サイズ・URL等を検証してから保存します。公開revisionと取得の間に版が変わった場合や通信・保存失敗時は、その半期の保存済み正常結果を残します。
- 一覧と名称対応表の保存は独立しており、一方の失敗で他方の正常な更新を取り消しません。
- 保存済み一覧は半期中オフラインでも表示します。4月1日・10月1日の切替後と今回の初回移行では一覧を削除し、再認証を必要とします。個人設定は保持します。詳しくは[非公開データの管理](private-data-lifecycle.md)を参照してください。

## 画面と端末内設定

- カテゴリ順とリンク順はAPIの順序を使います。通常表示ではお気に入りを先頭にまとめ、検索中はWeb版と同じ正規化・かな／ローマ字展開・一致度の順で結果を並べます。
- 設定の「一覧」→「リンクの開き方」で、HTTPSリンクを「外部で開く」または「アプリ内で開く」から選べます。未設定時の既定値はアプリ内です。保存済みの選択は保持します。外部はiOSの `openURL`、アプリ内は `SFSafariViewController` を全画面で表示します。`jrshikoku:` リンクは設定に関係なく対応アプリへ渡します。開けない場合は従来の案内を表示します。
- HTTPSリンクの行を長押しすると、設定と逆の開き方をその1回だけ選べます。設定値は変更しません。長押しではお気に入り、色変更、非表示も操作できます。お気に入りと非表示はスワイプからも操作できます。色は既定色に戻せます。
- 右上の「非表示のリンク」では、利用者が非表示にしたリンクを1件ずつ再表示できます。API側が非表示にしたリンクはここに出しません。
- お気に入り・非表示・色変更はリンクIDをキーに端末内へ保存します。APIから一時的に消えたリンクの設定も削除しません。Web版の個人設定とは同期しません。

## 確認範囲

認証前の拒否、非表示リンクの応答除外、ランダムrevisionの200/304・競合時の一意性、取得応答とrevisionの対応をAPIの架空データテストで確認します。iOS SDKビルド・公開IPA・実機は[検証記録](verification.md)で区別します。学校の実データはリポジトリやテストへ保存しません。

### 画面上の更新操作（2026-09-26）

更新操作と「一覧は最新です」等の取得結果は、設定の「データ取得」→「一覧・名称対応表」に移す。一覧タブの更新ボタン・引っ張って更新・更新メッセージを削除し、未取得時はデータ取得画面への入口を表示する。起動・タブ選択時のrevision確認は継続する。
