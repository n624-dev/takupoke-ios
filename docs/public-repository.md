# 公開リポジトリでの情報管理

## 公開するもの

- アプリのソースコードと開発用設定。
- 利用者が指定した学校公式の公開PDFの取得先URL（PDF本文や抽出結果は含めない）。
- 個人情報・秘密情報を含まないドキュメントと設定のひな形。
- 実在の学校資料・人物情報を含まない、完全に架空のテスト入力と期待結果。

教師名・教科名は実際のものを使わず、「架空教員A」「架空科目A」のように明確な架空値にします。入力だけでなく期待結果・エラー例・ログ例にも適用します。

実資料を名前だけ置き換えたものは、公開可能な架空データとみなしません。教材・資料の転載可否や、既存コード・依存ライブラリのライセンスも確認してから取り込みます。アプリ本体のライセンスは未選定です。依存ライブラリ・移植元のライセンスをアプリに同梱します。

## 含めないもの

- 学校の実際の PDF / XLSX、スクリーンショット、OCR 結果、抽出テキスト、CSV / JSON などの派生データ。
- 教員・生徒などの氏名、メールアドレス、学籍番号、アカウント情報、非公開の時間割・教室・行事情報。
- OneDrive の共有リンク、学校テナントやアカウントに関する情報、アクセス用ブックマークなど。
- Apple ID、パスワード、トークン、秘密鍵、署名証明書、プロビジョニングプロファイル。
- 実データの入った端末 DB、バックアップ、クラッシュログ、デバッグ出力。

実資料は原則としてリポジトリ外に保管します。必要なローカル作業用には `.gitignore` 対象の `private/`、`local-data/`、`secrets/` を使用できます。これらを作成する必要はありません。

`.gitignore` は誤追加を減らす補助です。すでに追跡しているファイルや `git add -f` には効かず、Swift・Markdown・JSON 内の秘密情報も検出しません。

PDF / XLSX / CSV などは初期設定でまとめて除外しています。将来、架空の比較テストデータを追加する場合は、内容を確認したうえで対象ファイルのみ `.gitignore` に例外を追加してください。

## PDFの全文診断

`DEBUG && TAKUPOKE_INTERNAL_DIAGNOSTICS`の内部Debug版では、通常時間割・試験・試験返却PDFの全文診断をコピーできます。公開版では従来の全文・更新診断コピーを無効にします。今回承認された返却PDFの位置情報専用操作だけを例外とし、文字列値を持たない数値・真偽値型の出力に限定します。配布検証は診断マーカー・コピー文言の実行ファイルへの混入を検出します。PDF本文・教員名・科目名・位置情報を含むため、コピー内容は非公開の開発相談でのみ扱い、公開Issue・リポジトリ・CI・Releaseへ貼り付けません。アプリは資料種別ごとに最新1回分をメモリに保持し、手動でクリップボードへコピーします。全文診断の永続保存・自動送信は行いません。検証には独立した架空データを使います。

## コミットのメールアドレス

Git のコミットには作者とコミッターの名前・メールアドレスが保存され、push すると履歴とともに公開されます。コミット作成前に GitHub の非公開用 `noreply` アドレスを設定し、学校や私用のメールアドレスは使いません。非公開にするのは実際のメールアドレスであり、公開用ユーザー名と `noreply` アドレスは履歴に残ります。

このデバイスのリポジトリには、公開用ユーザー名と GitHub のユーザー ID に基づく `noreply` アドレスを設定済みです。個人・学校のメールアドレスの読み取りや文書への転記は行いません。

リポジトリ専用の Git 設定は push / clone では引き継がれません。Windows でも clone 後、最初のコミットを作る前に、このリポジトリのディレクトリで以下を実行します。PowerShell と Git Bash の両方で使用できます。同じ GitHub アカウントを利用する場合の設定です。

```sh
git config --local user.name "n624-dev"
git config --local user.email "91827902+n624-dev@users.noreply.github.com"
git config --local user.useConfigOnly true
```

コミット前に以下で作者とコミッターの両方が `noreply` アドレスになっていることを確認します。環境変数や別の設定による上書きがある場合は解消してからコミットします。確認結果に実際のメールアドレスが含まれた場合、共有ログへ貼り付けないでください。

```sh
git var GIT_AUTHOR_IDENT
git var GIT_COMMITTER_IDENT
```

GitHub Actions で将来コミットを作る場合も、個人のメールアドレスを使わない設定にします。GitHub の Web 上での操作にはアカウント側のメール非公開設定も必要です。詳細は [GitHub の公式手順](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address) を参照してください。

## 追加・公開前の確認

```sh
git status --short --untracked-files=all
git diff
git diff --cached
```

初回のコミット前には上の公開用作者情報を設定し、追加するファイルの内容を確認します。履歴ができた後は、公開前に過去のコミットと作者情報も確認します。

```sh
git log --all --format=fuller
git ls-files
```

GitHub の公開リポジトリを作成・接続するときは、公開先と作者情報、履歴の内容を確認してから push します。

## Actions・IPA・AltStore Source

- 公開 CI の解析テストには架空データを使用する。学校資料をログや Actions artifact に出さない。
- 必要な秘密情報は GitHub Actions Secrets などで管理し、コード・設定・Source JSON に直書きしない。
- IPA に実資料、端末 DB、個人用設定、認証情報を同梱しない。
- Release 添付、Source JSON、スクリーンショット、ビルドログも公開対象として確認する。
- Source JSON には公開可能な配布情報だけを記載する。

秘密情報を誤ってコミットした場合、ファイルの削除だけでは履歴から消えません。公開・push を止め、必要に応じて認証情報を失効・再発行し、履歴や生成物からの除去を行います。

## 返却PDFの位置情報専用診断

通常のRelease・固定AltStore Sourceで、位置情報だけを取得できる診断対応版を配布する。
`PDFReturnGeometryRecorder.Snapshot`は数値・真偽値・その配列だけを値に持つ専用型で、
対象授業1件の元セル・本文取得範囲・実際の採用行ID、時限見出し・クラス欄・罫線の座標とIDを記録する。
ラベル本文の分類や削除は行わない。資料名・digest・日付文字列・授業名・教員・教室・画像を出力しない。
最大4,096件の近傍文字座標と4,096本の罫線、32個のセル断片、2MiBに制限し、省略はlimitedで示す。
端末内で保存済みPDFをStrictで再読取し、直近1回をメモリだけに保持する。Strictで読めない復旧採用PDFの診断は対象外である。DBへの保存と自動送信は行わない。
取得は授業詳細での手動操作、コピーは別の手動操作とし、クリップボードは端末内限定・10分で失効する。
次の処理開始と半期削除でメモリを消す。利用者が明示的に共有した場合だけ非公開の開発相談で扱う。

全文診断のコンパイル条件と既存IPA検査は維持し、全文コピー操作の混入検出も追加する。
数値専用マーカーがある場合でも全文マーカーとの併存を拒否する。公開検査・Native・全UI・公開ゲートを省略しない。
