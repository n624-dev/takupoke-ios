# 開発順序と完了条件

順序は①〜⑧に固定します。①は初回導入・実機起動に続き、Source 経由の更新後にメモが残ることを利用者報告で確認しました。必須の配布・更新経路が成立したため②へ進み、資料選択・取得・保存を実装しています。②では実機でOneDriveフォルダが選べないこと、個別資料が「ファイル」で開いた後に取得できることを確認しました。個別取得を基本とし、学校行事はWeb取得・端末内保持へ変更します。継続アクセスと新しい取得処理、①の Windows 固有の補足確認は引き続き必要です。③以降は未実装です。確認範囲は [検証記録](verification.md) に残します。

## ① 最小 SwiftUI アプリ・配布・実機アップデート

- [x] 最小 SwiftUI アプリのコードと Xcode プロジェクトを作成する（利用者から実機起動の成功報告あり）。
- [x] GitHub Actions の macOS runner で iOS をビルドする。
- [x] IPA を生成・公開する（Actions 成功・実機導入の利用者報告）。
- [x] AltStore Source とその公開先を構築する。
- [x] バージョン / build 番号と Source JSON を自動生成する（CI で生成成功、利用者から公開成功の報告あり）。
- [x] AltStore Classic の Source から iPhone に初回導入する（利用者報告）。
- [ ] このデバイスと Windows の両方で編集・push できることを確認し、Actions 経由で新しい IPA を公開する。
- [x] 同じ Source から iPhone 上のアプリを更新し、確認メモが保持される（案内した更新手順に対する利用者報告。正確な version / build の照合は未記録）。
- [ ] 失敗時に前回の正常な配布状態を維持することを確認する。
- [ ] このデバイスと Windows それぞれの Git のメールアドレス非公開設定と、開発から実機更新までの手順を記録する。

完了条件：初回導入と、その後の少なくとも一度の更新を実機で確認する。アプリ本体機能に進む前に、必須の配布・更新経路を成立させる。

- [x] フォルダ選択を検証する（利用者のOneDriveではグレーアウトして選択不可）。
- [ ] 個別資料のブックマークによる継続アクセスを検証する。
- [ ] 通常時間割 PDF・時間割変更 XLSX の修正版の取得と、学校行事 PDF のWeb取得・条件付き更新を実機で確認する。
- [ ] アプリ再起動後のアクセス、オフライン、権限喪失、再選択を検証する。
- [x] 取得用の一時コピーの削除と、途中終了後の回収を実装する。保存失敗時の巻き戻し・復旧をローカル Swift テストで確認（File Provider の中止動作は実機確認待ち）。

完了条件：実機で取得経路と継続アクセスの成立範囲を確認し、取得できない場合の状態を明示できる。

選択方法・制限・確認項目は [学校資料の選択・取得](materials.md) を参照してください。
