# 開発順序と完了条件

順序は①〜⑧に固定します。現在は方針の文書化と Git 管理の準備まで完了しており、以下は未実装です。実機が必要な検証は実施結果を記録し、CI の成功だけで完了扱いにしません。

## ① 最小 SwiftUI アプリ・配布・実機アップデート

- [ ] 最小 SwiftUI アプリを作成する。
- [ ] GitHub Actions の macOS runner で iOS をビルドする。
- [ ] IPA を生成・公開する。
- [ ] AltStore Source とその公開先を構築する。
- [ ] バージョン / build 番号と Source JSON を自動更新する。
- [ ] AltStore Classic の Source から iPhone に初回導入する。
- [ ] このデバイスと Windows の両方で編集・push できることを確認し、Actions 経由で新しい IPA を公開する。
- [ ] 同じ Source から iPhone 上のアプリを更新し、バージョンの切り替わりを確認する。
- [ ] 失敗時に前回の正常な配布状態を維持することを確認する。
- [ ] このデバイスと Windows それぞれの Git のメールアドレス非公開設定と、開発から実機更新までの手順を記録する。

完了条件：初回導入と、その後の少なくとも一度の更新を実機で確認する。アプリ本体機能に進む前に、必須の配布・更新経路を成立させる。

## ② OneDrive / File Provider から PDF・XLSX を取得

- [ ] iOS 標準の「ファイル」から資料へアクセスする。
- [ ] フォルダ選択と継続アクセスを優先して検証する。
- [ ] 通常時間割 PDF、学校行事 PDF、時間割変更 XLSX を取得する。
- [ ] アプリ再起動後のアクセス、オフライン、権限喪失、再選択を検証する。
- [ ] 取得・解析用の一時ファイルを処理後に削除し、失敗・キャンセル・異常終了後にも蓄積しない仕組みを整える。

完了条件：実機で取得経路と継続アクセスの成立範囲を確認し、取得できない場合の状態を明示できる。

## ③ XLSX 解析

- [ ] `denpa-schedule-csv` の解析仕様を確認・文書化する。
- [ ] 日付正規化、クラス展開、変更前後科目、教員、教室、備考などを Swift に移植する。
- [ ] 架空の入力で既存実装と結果比較を行う。
- [ ] 不正・未対応の入力を正常結果と区別する。

完了条件：比較テストが通り、残る差異があれば理由と対応方針を明文化している。

## ④ PDF 解析

- [ ] PDFKit を使用して通常時間割と学校行事を解析する。
- [ ] 学校の実際の書式に合わせて処理する。
- [ ] 曖昧・未対応の内容を推測で反映しないことを確認する。

完了条件：対象書式を検証し、解析できる範囲とできない範囲を明示できる。

## ⑤ 端末内 DB・時間割統合

- [ ] 保存方式とデータモデルを確定する。
- [ ] 元ファイルの状態、更新日時、解析結果、時間割変更を保存する。
- [ ] 通常時間割・学校行事・時間割変更の統合規則を定義し実装する。
- [ ] 失敗時に既存データを保持する反映処理を実装する。

完了条件：端末内だけで統合結果を再現でき、解析途中の失敗で正常データが失われない。

## ⑥ SwiftUI 本体 UI

- [ ] 時間割・学校行事・時間割変更を表示する。
- [ ] 資料の選択状態、更新日時、解析状態を表示する。
- [ ] 未解析・曖昧・更新失敗を利用者が識別できるようにする。

完了条件：通常利用と更新状態の確認をアプリ内で行える。

## ⑦ ファイル更新・差分反映・障害復旧

- [ ] ファイル更新時に再取得・再解析する。
- [ ] 差分を時間割へ反映する。
- [ ] 取得・解析失敗時に前回正常データを維持し、失敗を表示する。
- [ ] 再試行・再選択による復旧を検証する。

完了条件：更新成功、取得失敗、解析失敗、復旧の各経路でデータ整合性を確認する。

## ⑧ 通知・バックグラウンド更新

- [ ] UserNotifications で通知を実装する。
- [ ] BackgroundTasks を使用する。
- [ ] 起動時・復帰時・手動更新を整える。
- [ ] 実機でバックグラウンド動作を検証し、成立する範囲だけ仕様化する。

完了条件：権限や実行条件を含めて実機確認し、確認済みの動作と制約を記録する。
