# 開発順序と完了条件

順序は①〜⑧に固定します。①は初回導入・実機起動に続き、Source 経由の更新後にメモが残ることを利用者報告で確認しました。必須の配布・更新経路が成立したため②へ進み、資料選択・取得・保存を実装しています。②では実機でOneDriveフォルダが選べないこと、個別資料が「ファイル」で開いた後に取得できることを確認しました。個別取得を基本とし、学校行事はWeb取得・端末内保持へ変更しました。続く修正版ではPDF・XLSX取得、学校行事のWeb取得・保持・更新確認と、再起動後の個別資料の再取得が成功したと報告されました。③のSwift解析・結果確認画面と架空データの比較テストを実装しました。実機で報告された数式・学年表記の解析エラーを修正し、警告からの閲覧用プレビューを追加しました。続いて利用者から実機解析の成功とAIクラスの表記揺れが報告され、同一クラスとの確認に基づいて `AI_数字` へ統一しました。AI表記統一も実機で動作したと報告されました。警告時の操作・失敗後の保持は実機確認待ちです。未ダウンロード状態・障害時の実機確認と①のWindows固有の補足確認は残っています。確認範囲は [検証記録](verification.md) に残します。

## ⑤ 端末内 DB・時間割統合

[SQLite設計案](local-database-design.md)で、原本・解析結果・採用版の分離と、適用範囲・未確定状態・保持の条件を整理しています。通常の取得・解析のDB保存と読出しを実装し、アプリの保存先をSQLiteへ接続しました。開発版では旧JSONを移行せず、資料を再取得・再解析します。保存の失敗時は前回正常解析とその原本を保持します。利用者から切替後の確認が全て成功したと報告されましたが、正確な実機ビルドや個別の失敗条件の実機検証は未記録です。採用版・時間割統合・将来の保持規則は未実装で、資料の更新契約等は確認待ちです。

- [ ] 保存方式とデータモデルを確定する。
- [x] 元ファイルの状態、更新日時、解析結果、時間割変更をSQLiteへ保存する（Linuxの架空データで検証。利用者から切替後の確認成功報告あり）。
- [ ] 通常時間割・学校行事・時間割変更の採用版を保存する統合規則を定義し実装する（画面上の週表示には既存分類と変更を投影。試験・返却PDFも端末内保存して授業枠ごとに統合する実装を追加。新しい部分は実機確認待ち）。
- [ ] 失敗時に既存データを保持する反映処理を実装する。

完了条件：端末内だけで統合結果を再現でき、解析途中の失敗で正常データが失われない。
