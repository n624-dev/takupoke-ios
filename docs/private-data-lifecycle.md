# 非公開データの管理

## 今回確定した仕様

- 一覧の全リンクは認証必須。配信元の非表示リンクは応答から除外する。個人の非表示設定とは別扱い。
- 一覧と名称対応表は一回のOIDC認証で取得する。`openid mapping.read links.read` を要求し、Refresh Tokenは導入せず、Access Tokenを永続保存しない。
- 起動時は公開のランダムrevisionだけを確認する。更新の取得は利用者の操作による認証後に行い、片方の失敗で他方の正常結果を破壊しない。
- 保存済みの一覧は、その半期中は認証なし・オフラインで表示する。
- 日本時間4月1日・10月1日の切替後、学校ファイル・解析結果・ブックマーク・名称対応表・一覧・診断を端末内から削除する。今回の管理方式を初めて導入するときも削除する。
- 個人設定（クラス、お気に入り、色、非表示、ブラウザ選択）、公開行事、OneDrive上の原本は保持する。
- 公開版からすべての診断コピーUIを除外する。全文診断の生成・エンコード処理は `DEBUG && TAKUPOKE_INTERNAL_DIAGNOSTICS` の場合だけコンパイルする。内部ビルドでも学校資料を公開物に含めない。

## 削除と競合対策

学校データを表示・読み込む前に保存期間の管理ファイルを確認する。期間切替時はデータを表示するViewを外し、ファイル監視・認証・取得を停止してワーカーの終了を待つ。保存先を閉じ、アプリ所有の保存先だけを削除する。全削除が成功した後に期間を記録し、空の保存先を開く。途中失敗では古いデータの利用を止め、次回の再試行でも削除を続ける。

起動・復帰時に確認し、表示したままの半期切替も定期チェックする。アプリが停止している間の自動削除は保証せず、次回利用時に先に削除する。判定には端末の日本時間を使う。改造端末・アプリ改変・端末時計の偽装まで防ぐDRMではない。

## 検証

実装中。架空データによる年度・半期境界、削除対象、部分失敗からの再試行、認証・revisionの試験を追加する。CIと実機の確認結果は分けて記録する。
